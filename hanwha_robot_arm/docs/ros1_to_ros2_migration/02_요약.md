# HCR-5 ROS1→ROS2 포팅 요약

## 왜
`hanwha_robot_arm` 저장소 전체가 2023년 ROS1(catkin + MoveIt1 Setup Assistant) 기준으로 작성됨. 환경에는 ROS2 Jazzy만 설치되어 있어 그대로 빌드 불가. MoveIt 테스트를 위해 ROS2/MoveIt2로 정식 포팅.

## 뭘 했나
- `hcr_robot_description`: catkin → `ament_cmake` 전환, `ros2_control`(mock hardware) 추가, `display.launch.py` 신규
- `hcr_moveit_config`(신규 패키지): SRDF/kinematics.yaml은 기존 그대로 재사용, `ros2_controllers.yaml`/`moveit_controllers.yaml`/`demo.launch.py`/`moveit.rviz`는 ROS2 Jazzy 표준 레이아웃(panda_moveit_config 레퍼런스 참고)으로 신규 작성
- 옛 `hcr_moveit`(ROS1)은 `COLCON_IGNORE` 처리 → 이게 원래 catkin 에러의 직접적인 해결책

## 안 됐던 것 → 원인 → 조치 (총 4건)

| # | 증상 | 원인 | 조치 |
|---|---|---|---|
| 1 | `move_group` 즉시 죽음 (`InvalidParameterTypeException`) | `joint_limits.yaml`의 `max_velocity: 100`이 정수로 파싱됨. ROS2는 파라미터 타입을 엄격히 검사 | `100` → `100.0`으로 실수화 |
| 2 | `move_group` 즉시 죽음 (`Planning plugin name is empty`) | ROS1은 `planning_plugin`을 launch xml에서 지정했지만, MoveIt2는 `ompl_planning.yaml` 안에 직접 있어야 함 | `planning_plugins`/`request_adapters`/`response_adapters` 키 추가 |
| 3 | RViz "Plan & Execute" 항상 실패 (`No acceleration limit was defined`) | `has_acceleration_limits: false`라서 MoveIt2 기본 시간파라미터화(TOTG)가 궤적 생성 불가 (ROS1의 옛 알고리즘은 없어도 됐음) | `has_acceleration_limits: true`, `max_acceleration: 100.0`으로 설정 |
| 4 | 컨트롤러 스포너 실패 + RViz "aborted" (근데 실제로는 팔이 움직임) | `demo.launch.py`를 실수로 두 번 동시 실행해서 노드/토픽/액션이 충돌 | 중복 프로세스 kill, 이후 launch는 항상 하나만 사용자가 직접 실행 |

## 결과
`colcon build` 전체 성공, `ros2 launch hcr_moveit_config demo.launch.py`로 RViz + move_group + 컨트롤러 정상 기동, 자동 스크립트로 plan+execute까지 `SUCCEEDED` 확인.

## 앞으로 유의할 점
- `max_velocity`/`max_acceleration` 값은 테스트용 임시값(100.0) — 실기 연동 전 Hanwha 공식 스펙값으로 교체 필요
- 같은 launch를 중복 실행하지 말 것 (문제 4 원인)
- 다른 HCR 모델 포팅 시 `01_상세_가이드.md`의 5장(향후 참고 사항) 참고

# HCR-5 실기 연결 현황 (2026-07-28 조사)

> **한 줄 요약** — 이 리포의 HCR-5 자산은 **mock hardware 까지만** 동작한다. 한화 **공식** ROS 2 드라이버는 없다.
> 그러나 **비공식 커뮤니티 ROS 2 드라이버가 실재하며, 실물 제어까지 구현되어 있다** — `ros2_control` 하드웨어 플러그인을 그대로 갈아끼우는 **(A) 경로가 성립한다.**

**대상 실물**: **HCR-5** (구형, 한화정밀기계). 단종된 지 오래된 모델이다 (Mark 확인, 2026-07-28).
스펙은 **HCR-5 User Manual v2.0 (2018-11) Appendix F·G** 기준이며, HCR-5A(Advanced) 카탈로그값이 아니다.

## 2. 이 리포에 없는 것

`hcr_robot.ros2_control.xacro` 의 하드웨어 플러그인이 `mock_components/GenericSystem` 하나뿐이다 — 받은 명령을 그대로 상태로 되돌려주는 가짜 하드웨어다.

없는 것: 실기용 `SystemInterface` 구현 · 로봇 IP·포트 설정 · 통신 프로토콜 구현.
원본 저장소(`pondinesh006/hanwha_robot_arm`)도 *"Steps for Running on Robot: under development"* 상태다. **의도적으로 mock 까지만 한 작업이다.**

### 갈아끼울 자리 — 이 브랜치엔 아직 없고, simulation 쪽에 있다

⚠️ **이 브랜치의 `hcr_robot.xacro` 에는 인자화가 없다.** 플러그인이 `hcr_robot.ros2_control.xacro` 안에 고정되어 있다.
`markch/simulation_skeleton` 계열에서는 인자화되어 있어 (2026-07-28, MuJoCo 작업) 교체가 한 줄이다:

```bash
xacro hcr_robot.xacro hardware_plugin:=<드라이버>/<SystemInterface>
```

인자화는 **기본값이 종전과 같아 MoveIt2 경로에 무영향**이므로, §1 검증 결과는 두 계열에서 동일하다.

### 3.3 구조 — 매뉴얼에 없던 통로의 정체는 **Rodi-X 플러그인**

| 층 | 내용 |
|---|---|
| **로봇 쪽** | `hcr_plugin/ROS2.asar` 를 티치펜던트에 **Rodi-X 플러그인**으로 설치 → 데몬이 **TCP 6667** 개방 |
| **PC 쪽** | `hcr_control` 패키지 = **`hardware_interface::SystemInterface` 구현** |
| **플러그인 이름** | **`hcr_control/RobotSystem`** ← 우리 xacro 의 `hardware_plugin:=` 에 넣을 값 |
| 통신 | POSIX TCP 소켓 (`socket`/`connect`/`send`/`recv`) + 텍스트 명령 |
| `read()` | `GET_JOINTS` (관절) · `GET_GPI` (디지털 입력 8ch) |
| `write()` | **`MOV j1 j2 j3 j4 j5 j6\r\n`** (도 단위, `%7.2f`) · `GPO` 8ch. 값이 바뀔 때만 전송 |

`hcr_control.xml` 이 pluginlib 로 선언한다:

```xml
<class name="hcr_control/RobotSystem" type="hcr_control::RobotSystem"
       base_class_type="hardware_interface::SystemInterface"/>
```

**RoboDK 가 `RoboDK.asar` 를 넣는 것과 동일한 메커니즘이다.** 즉 §3.4 에서 확인한 "공식 매뉴얼에 외부 실시간 제어가 없다"는 사실은 맞지만,
**Rodi-X 플러그인 계층이 그 통로였다** — 매뉴얼이 다루지 않는 확장 지점이다.

### 3.4 공식 매뉴얼이 말하는 것 (Appendix F · 목차 전체)

| 항목 | 값 |
|---|---|
| **External communication** | **TCP/IP · Modbus TCP** · CC-link / Profinet / EtherNet-IP (optional) |
| I/O (Controller) | Digital In 16 · Digital Out 16 · Analog In 2 · Analog Out 2 |
| I/O (Tool connector) | Digital In 4 · Digital Out 4 · Analog In 2 · EtherCAT 1 (**툴 부착용**) |

목차 전체(16장 + Appendix A~H)에서 외부와 이어지는 통로는 **7.5 Modbus TCP**(I/O·레지스터 등록·조회), **13장 비전 장비 연동**, **14.2 네트워크 설정**뿐이다.
9.20 Script 도 **Viewer**(조회 전용)다. **관절 궤적을 보내는 기능은 매뉴얼에 없다** — 위 플러그인 계층이 그것을 메운다.

## 4. 실기 연결 경로 — (A) 로 간다

| 경로 | 상태 |
|---|---|
| **(A) ros2_control SystemInterface** | ✅ **실증 구현 존재** (`hcr_control/RobotSystem`). 현 구조 그대로, 플러그인 이름만 교체 |
| (B) 궤적 → Rodi 명령 브릿지 | (A) 가 HCR-5 에서 안 될 때의 대안으로만 유지 |

(A) 가 되면 `joint_trajectory_controller` · MoveIt2 · 하드웨어 추상화 경계(N6·F7.3)가 **전부 그대로 성립한다.**

### 확인해야 할 위험 4가지

1. **HCR-3A 용이고 우리는 구형 HCR-5** — `ROS2.asar` 가 구형 Rodi 에서 동작하는지가 최대 관건.
   RoboDK 문서 기준 Rodi **2.001.003.012 이상** 필요하고, HCR-5 매뉴얼이 v2.001 대이므로 가능성은 있으나 **미검증**이다.
2. **명령 분해능 `%7.2f` = 0.01°** — reach 915 mm 에서 약 **0.16 mm** (0.01° = 1.745e-4 rad × 915 mm).
   로봇 반복정밀도 ±0.1 mm 와 같은 자릿수라 **선 품질의 병목이 될 수 있다.** 선화 정밀도 목표와 함께 따져야 한다.
3. **`read()` 가 `send`→`recv` 블로킹** — controller_manager 100 Hz 를 유지하려면 왕복이 10 ms 안에 끝나야 한다. 네트워크 지연에 취약.
4. **`MOV` 를 로봇이 어떻게 해석하는가** — 점대점(movej)인지 서보 추종인지에 따라 연속 궤적 품질이 갈린다. `hcr_plugin/ROS2` 소스 확인 필요.

## 5. 실기 연결 전 반드시 교체할 값 — 공식 스펙 대조

### 5.1 관절 속도 한계 — 현재 실기의 약 32배

`joint_limits.yaml` 의 `max_velocity: 100.0` (rad/s) = **5729 °/s**.
**HCR-5 공식 최대 관절속도는 180 °/s (= 3.1416 rad/s)** — Appendix G 가 *"maximum speed of 180°/sec which can be generated at the robot joint"* 로 명시.

`velocity_scaling_factor` 0.1 로 큰 이동(joint_1 약 4 rad)을 계획시킨 실측:

```
joint       peak rad/s  peak deg/s   HCR-5 공식     배율
joint_1          6.002       343.9         180      1.91x
```

**스케일링 0.1 에서도 약 1.9배, 1.0 이면 약 19배**다. URDF `<limit ... velocity="100"/>` 과 `joint_limits.yaml` **양쪽 모두** 고쳐야 한다.

`max_acceleration: 100.0` 도 임시값이다. **공식 매뉴얼에 관절 최대 가속도 항목이 없다** — Appendix G 의 정지거리·정지시간(J1 34.67°/0.61 s, J2 31.60°/0.55 s, J3 29.08°/0.51 s, 브레이크 체결 0.03 s)에서 역산하거나 벤더에 문의해야 한다.

### 5.2 관절 가동범위 — CAD 변환값이라 실기와 불일치

| 관절 | URDF | **HCR-5 공식 (Appendix F)** | 문제 |
|---|---|---|---|
| joint_1 | **0° ~ +360°** | ±360° | **음수 방향 불가** |
| joint_2 | ±90° | ±360° | 크게 좁음 |
| joint_3 | ±130° | **±165°** | 좁음 (J3 만 별도 제한이 실제로 존재) |
| joint_4 | ±170° | ±360° | 좁음 |
| joint_5 | ±120° | ±360° | 좁음 |
| joint_6 | **0° ~ +360°** | ±360° | **음수 방향 불가** |

공식값은 `±360° (J3: ±165°)` 한 줄이다. joint_1·6 의 음수 불가가 특히 문제로,
**IK 해가 있는데도 F4.2 가 계획 실패로 떨어질 수 있다.**

> URDF 한계를 실기보다 **좁게** 두는 것은 안전하지만, 넓게 두면 로봇이 자체 정지를 건다 (매뉴얼 8.5 *Exceeding Safety Limit of Joints*).

### 5.3 effort

URDF `effort="100"` 도 CAD 기본값이다. 공식 매뉴얼에 관절 토크 항목이 없어 벤더 문의 대상이다.

### 5.4 확정된 실물 제원 (Appendix F)

| 항목 | 값 |
|---|---|
| 자유도 / 가반하중 / 작업반경 | 6 / 5 kg / 915 mm |
| **관절 가동범위** | **±360° (J3: ±165°)** |
| **반복정밀도** | **±0.1 mm** |
| 본체 중량 / 설치 바닥 | 20 kg / Ø150 mm |
| IP 등급 | IP54 (암) / IP20 (컨트롤러) |
| 전원 | 100~240 VAC, 50~60 Hz |

리포 README 의 *"915mm / 5kg / ±0.1mm"* 와 일치 — **실물이 구형 HCR-5 임이 문서로도 확인된다.**

## 7. 재현 명령어

```bash
cd Nyang_Nyang_Atlier/src/moveit2
./run_container.sh build          # moveit2_dev:jazzy 미빌드 시 (20~40분)
./run_container.sh shell
# ─ 컨테이너 안 ─
cd ~/ws_moveit2 && colcon build --symlink-install && source install/setup.bash
ros2 launch hcr_moveit_config demo.launch.py    # ⚠️ 두 번 실행 금지 (포팅 문서 문제 4)
```

**상태 확인** (다른 터미널):

```bash
ros2 control list_controllers            # 둘 다 active 여야 함
ros2 control list_hardware_components    # plugin name 으로 mock/실기 판별 ★
ros2 topic echo /joint_states --once
```

`list_hardware_components` 의 `plugin name` 이 **지금 무엇에 연결되어 있는지 판별하는 가장 빠른 방법**이다.

**RViz 없이 팔 움직이기**:

```bash
ros2 topic pub -1 /hcr_arm_controller/joint_trajectory trajectory_msgs/msg/JointTrajectory "{
  joint_names: [joint_1, joint_2, joint_3, joint_4, joint_5, joint_6],
  points: [{positions: [0.5, 0.0, 1.5669, -1.59, -1.4695, 0.0], time_from_start: {sec: 2}}]}"
```

# frontend — 운영 화면 (React)

**미착수 — 자리만 잡아 둔 상태.** 아래는 방침이며 코드는 아직 없다.

## 화면이 답해야 하는 것

사용자가 하려는 일 다섯 가지(`../README.md` "사용자가 하려는 것")가 그대로 화면이 된다.

| 화면 | 하는 일 | 근거 |
|---|---|---|
| 업로드 | 이미지를 올리고, 거부되면 **사유를 본다** | F6.1 · F1.2 |
| 진행 | 현재 상태·스트로크 진행률·경과 시간 | F6.2 |
| 중간 확인 | 계획 대비 차이 정보를 보고 **계속/중단을 누른다** | F8.1 |
| 정지 | 긴급정지(폐기) · 일시정지(보존)·재개 — **둘은 다른 버튼이다** | F6.4 · F6.5 |
| 이력 | 지난 작업 목록·상세(입력·계획·결과·소요시간·실패 스트로크) | F6.3 |

## 두 경로로 말한다

```
상태 구독 ── ws://localhost:9090 (rosbridge) ── job_manager    ← 실시간
명령 발행 ── ws://localhost:9090 (rosbridge) ── job_manager    ← 정지·재개·계속/중단
업로드·이력 ── HTTP ── backend(Node.js)                        ← 파일과 기록
```

- **roslibjs 로 MoveIt 액션을 직접 호출하지 않는다** (SA §5.2). rosbridge 는 액션을
  지원하지 않고, MoveIt 호출은 `job_manager` 가 서버측에서 한다. 화면이 부르는 것은
  그 노드의 **서비스·토픽뿐**이다.
- 진행률을 백엔드가 중계하지 않는 이유는 지연 때문이다. 반대로 **이력 저장은 백엔드가
  따로 구독한다** — 브라우저를 닫아도 기록은 남아야 한다.

## 긴급정지 버튼에 대해

F6.4 는 "어떤 상태에서든 즉시"(N4)를 요구하지만, 이 경로는 브라우저 → ws → 노드를
거친다. **Phase 1 은 랩에서 사람이 지켜보는 환경이라 이 지연을 감수한다** — 물리 E-stop
버튼과 안전 센서는 BRD §1.2 의 Phase 3(사업화 전제) 항목이다. 화면에서 이 버튼은
일시정지와 **눈에 띄게 다르게** 생겨야 한다. 하나는 작업을 버리고 하나는 이어 그린다.

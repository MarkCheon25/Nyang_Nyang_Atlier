## 2. 기능 흐름

기능 단위 블록이다. 각 블록은 앞 블록의 산출물을 입력으로 받고, 자기 결과를 파일로 떨군다.
**블록 하나만 따로 돌릴 수 있어야 한다** — 매번 처음부터 다시 하지 않는다.

```
  최초 1회                                      매 작업
 ┌──────────────────────┐                    ┌──────────────────────┐
 │ [A] 인쇄물·왜곡 점검  │                    │ [C] H 갱신           │
 │     장비 일부         │───┐                │     카메라 1초       │
 └──────────────────────┘   │                └──────────┬───────────┘
                            ▼                           ▼
                 ┌──────────────────────┐    ┌──────────────────────┐
                 │ [B] 기준 확정 + 평면  │───▶│ [D] 종이 위치 인식    │
                 │     카메라 + 로봇     │    │     카메라           │
                 └──────────────────────┘    └──────────┬───────────┘
                                                        ▼
                                             ┌──────────────────────┐
                                             │ [E] 검증             │
                                             └──────────────────────┘
```

### A. 인쇄물 · 왜곡 점검

| 항목 | 내용 |
|---|---|
| 입력 | 설정 (마커 규격 · 해상도) |
| 하는 일 | ① 기준 마커 시트 PDF 생성 ② 공장 intrinsic 읽기 ③ **직선 테스트** ④ (필요시) 보정 후 재검사 |
| 산출 | 마커 시트 PDF · `distortion.yaml` |
| 판정 | 곧은 물체를 화면 **가장자리**에 걸쳐 찍고 휘는지 본다. 안 휘면 왜곡 무시 → 여기서 끝 |
| 장비 | 시트 생성은 **장비 불필요** · 왜곡 점검은 카메라만 |

> 호모그래피는 직선을 직선으로 보내는 변환이라, 왜곡이 남으면 **가운데는 맞고 가장자리에서 어긋난다.**
> D456 은 FOV 가 90°로 넓어 그냥 넘길 수 없다. 다만 정밀하게 구할 필요는 없고 **있는지 확인만** 하면 된다.
> ⚠️ D400 계열은 컬러 왜곡계수가 **전부 0으로 보고되는 경우가 흔하다.** 렌즈가 완벽해서가 아니므로
> 공장값보다 ③의 눈검사를 우선한다. ④(ChArUco 정식 캘리브레이션)까지 갈 확률은 낮다.

### B. 기준 확정 + 작업평면 — 최초 1회

| 항목 | 내용 |
|---|---|
| 입력 | 붙여 놓은 기준 마커 · (있다면) `distortion.yaml` |
| 하는 일 | 마커 기준점을 펜 끝으로 짚어 **base 좌표 확정** → 같은 데이터로 작업평면 산출 |
| 산출 | `reference.yaml` — 마커 코너의 base 좌표 · 평면 (법선, 오프셋) · 터치 잔차 |
| 판정 | 평면 맞춤 잔차 · 마커 간 실측 거리와 인쇄 규격의 대조 |
| 로봇 | **움직인다** — §3.4 안전 조건을 먼저 볼 것 |

마커 치수를 알므로 **마커당 1~2코너만 짚어도 나머지 코너는 계산으로 전개**된다.
이 값은 마커가 떨어지지 않는 한 영원히 유효하다.

### C. `H` 갱신 — 매 작업 전

| 항목 | 내용 |
|---|---|
| 입력 | `reference.yaml` + 지금 찍은 마커 프레임 |
| 하는 일 | 관측 코너 ↔ 기준 base 좌표를 짝지어 **`H` 를 그 자리에서 다시 푼다** → 직전 `H` 대비 드리프트 판정 |
| 산출 | `homography.yaml` — `H` · 대응쌍 잔차 · 드리프트(mm) |
| 판정 | 잔차가 크면 마커가 들떴거나 왜곡이 남은 것. 드리프트가 임계를 넘으면 **사람을 부른다** |
| 장비 | **카메라만, 1초** |

### D. 종이 위치 인식 — 매 작업

| 항목 | 내용 |
|---|---|
| 입력 | `homography.yaml` + 종이가 놓인 프레임 |
| 하는 일 | 종이 모서리 검출 → `H` 로 base 좌표 환산 → 종이 좌표계(원점·회전) 산출 |
| 산출 | `paper.yaml` — 종이 원점·회전·실측 치수 |
| 판정 | 검출 치수가 A4(210×297mm)와 맞는지. 어긋나면 오검출 |
| 미정 | 🔴 **마커 부착 vs 외곽선 검출** — 지그 제작과 함께 정한다. 외곽선은 부착물이 없어 편하지만 흰 종이/흰 작업대면 대비가 안 나온다 |

### E. 검증

| 항목 | 내용 |
|---|---|
| 하는 일 | 알려진 점 재현성 · base→이미지→base 왕복 오차 · 같은 장면 반복 촬영 흔들림 |
| 산출 | 오차 리포트 — 파이프라인이 이 값을 믿어도 되는지의 근거 |

## 3. 뼈대

### 3.1 파일 구성

기능 단위로 자른다. 계층(공통)과 블록(절차)을 갈라 둔다.

| 파일 | 역할 | 블록 | 장비 없이 검증 가능? |
|---|---|---|---|
| [`cal.py`](cal.py) | CLI 진입점 · 서브커맨드 분배 | 전체 | — |
| [`cal_config.py`](cal_config.py) | 설정 로드 · 결과/원자료 입출력 | 공통 | ✅ |
| [`cal_geometry.py`](cal_geometry.py) | 좌표 변환 · 평면 · 호모그래피 수학 (순수 함수) | 공통 | ✅ **합성 데이터로 단위테스트** — **구현 완료** |
| [`cal_camera.py`](cal_camera.py) | 카메라 I/O · 왜곡 점검 | A | ❌ |
| [`cal_markers.py`](cal_markers.py) | 마커 검출 · 서브픽셀 · ChArUco | B·C·D | ✅ **합성 영상으로 검증** — **구현 완료** |
| [`cal_robot.py`](cal_robot.py) | 로봇 자세 취득 · 터치 기록 | B | ❌ |
| [`cal_board.py`](cal_board.py) | 인쇄물 생성 | A | ✅ **장비 불필요** — **구현 완료** |
| [`cal_calibrate.py`](cal_calibrate.py) | 기준 확정 + `H` 갱신 — **본체** | B·C | 일부 |
| [`cal_runtime.py`](cal_runtime.py) | 종이 인식 + 검증 | D·E | 일부 |
| [`cal_simulate.py`](cal_simulate.py) | **합성 검증 도구** — 실셋업을 기하로 재현해 검출·`H` 정확도 측정 | A·E 보조 | ✅ **장비 불필요** — **구현 완료** |
| [`cal_geometry_test.py`](cal_geometry_test.py) | `cal_geometry` 단위테스트 33개 | 공통 | ✅ **장비 불필요** — **구현 완료** |
| [`cal_markers_test.py`](cal_markers_test.py) | `cal_markers` 단위테스트 22개 — 합성 영상 검출 | B·C·D | ✅ **장비 불필요** — **구현 완료** |

`cal_geometry_test.py` 도 서브커맨드가 아니다. `python3 cal_geometry_test.py` 로 단독 실행되고,
파일명이 `*_test.py` 라 `pytest` 도 걷어 간다. **numpy 만 있으면 돈다** — cv2 는 교차 대조에만
쓰고 없으면 그 테스트만 건너뛴다 (`simulation_dev` 컨테이너에서 확인).

`cal_simulate.py` 는 `cal.py` 서브커맨드가 아니다 — 절차가 아니라 **개발용 계측기**라 따로 둔다.
`python3 cal_simulate.py` 로 바로 돌린다. 나오는 수치는 **인쇄물·검출 알고리즘의 상한**이지
실기 정확도가 아니다(렌즈 왜곡·마커 들뜸·조명·로봇 반복도가 빠져 있다). 실기 값은 블록 E 가 잰다.

### 3.2 명령

```
cal.py board      [--kind markers|charuco]   # [A] 인쇄물 생성   — 장비 불필요
cal.py distortion                            # [A] 왜곡 점검     — 카메라
cal.py reference                             # [B] 기준 확정+평면 — 카메라+로봇, 최초 1회
cal.py update                                # [C] H 갱신        — 카메라, 매 작업 전
cal.py paper                                 # [D] 종이 위치 인식 — 카메라, 매 작업
cal.py verify                                # [E] 검증
```

공통 옵션 `--config` · `--recompute`(계산만 다시) · `--dry-run`.
`check_prerequisites()` 가 선행 결과 유무를 보고, 없으면 무엇을 먼저 돌려야 하는지 짚어 준다.

### 3.3 주요 함수

스켈레톤은 각 파일에 있다. 축이 되는 것만 여기 적는다.

**`cal_geometry.py` — 카메라도 로봇도 없이 검증되는 유일한 계층**

| 함수 | 역할 |
|---|---|
| `pose_to_matrix` / `matrix_to_pose` | 로봇 자세 6값 ↔ 4×4. 🔴 **ZYX 오일러 · 도 단위** · 왕복 항등을 테스트로 건다 |
| `rvec_tvec_to_matrix` | OpenCV 표현 → 동차행렬. **규약 경계는 이 파일 하나로 몬다** |
| `fit_plane` / `plane_z_at` | 터치 점 → 평면 → 펜다운 z 의 출처 |
| `solve_homography` | 대응쌍(≥4) → `H`. intrinsic · `T_base→cam` · 펜 오프셋을 전부 흡수 |
| `homography_drift` | 두 `H` 가 같은 점을 얼마나 다른 곳으로 보내는지 — 최대 변위(mm) |

✅ **구현 완료** (2026-08-16). 단위테스트 33개 전부 통과 — [`cal_geometry_test.py`](cal_geometry_test.py).
**cv2 를 쓰지 않는다.** 이 계층이 검증의 바닥이라, cv2 로 풀고 cv2 로 검증하면 같은 구현을 두 번
보는 셈이 되어 서로의 오류를 가려 준다. 정규화 DLT + 가우스-뉴턴 정련을 직접 풀고, 테스트에서
cv2 와 **교차 대조**한다(cv2 가 있을 때만). 이 대조가 실제로 **N11** 을 잡아냈다.

**`cal_calibrate.py` — 본체**

| 함수 | 역할 | 블록 |
|---|---|---|
| `build_reference_map` | 짚은 점 + 인쇄 규격 → 마커 코너 전체의 base 좌표 | B |
| `build_work_plane` | 같은 터치 데이터에서 작업평면 | B |
| `pen_down_z` / `pen_up_z` | 평면 z ∓ 오프셋. **깊이 센서와 무관** | B |
| `compute_homography` | 대응쌍 → `H` + 잔차 | C |
| `detect_drift` | 직전 `H` 대비 변위를 임계와 견줌 | C |

**`cal_robot.py` — flange 만 본다**

| 함수 | 역할 |
|---|---|
| `get_flange_pose` | 현재 flange 자세. ⚠️ **`tcp` 가 아니다** — 📌 L14 는 닫혔지만(펜 TCP 실측·등록, 2026-08-16) flange 를 계속 쓴다. 이유는 `cal_robot.py` 머리주석 |
| `check_wrist_vertical` | 손목 수직 여부 — **호모그래피 방식이 서는 전제**. 통과해야 터치를 기록한다 |
| `prompt_touch` / `record_touch_point` | 사람이 조그로 짚고, 스크립트는 읽기만 (L21 대응) |
| `move_to` | 🔴 **봉인** — L21 이 닫히기 전까지 실기 호출 금지 |

### 3.4 아직 없는 것 — 채워야 서는 것들

| **N3** | 🔴 기준 마커 실물 | 인쇄·재단·부착. `cal.py board` 로 시트를 뽑는 것이 첫 단계 |
| **N4** | 🟡 판정 임계 | 호모그래피 잔차 · 드리프트 경고 임계 · 평면 잔차. 📌 **2026-08-16 — 평면 잔차만 물리에서 확정됐다.** 스프링 행정이 1.069mm 뿐이라 작업평면 z 가 **±0.4mm** 안에 들어야 한다(`260816-알트도르퍼` 실측, BRD R2 되먹임). 이건 선화 품질이 아니라 **펜이 종이에 닿느냐 긁느냐**의 조건이라 협상 대상이 아니다. 나머지 둘(H 잔차·드리프트)은 여전히 **선화 정밀도 요구에서 역산**해야 한다 — Mark 입력 대기 |
| **N5** | 🔴 종이 인식 방식 | 마커 부착 vs 외곽선 (블록 D) |

| **N7** | 🟡 기둥 강성 | 얼마나 흔들리는지 미측정. 블록 E `verify_repeatability` 가 그 실측치를 낸다 |
| **N9** | 🟡 **OpenCV 버전 분기** — 4.7 에서 aruco API 이름이 바뀌었고 5.0 에서 구 API 가 사라졌다. 양쪽 분기를 넣어 두었고 4.6·5.0 에서 검증 20/20 동일 통과. 04pc 의 호스트·컨테이너는 **전부 4.6**. 상세는 [`cal_readme.md`](cal_readme.md) §2 |
| **N10** | 🟡 **마커 4개는 여유가 0 이다** — 하나만 가려도 `H` 를 못 푼다(합성 검증 3/4 전부 실패). 가림·조명이 문제되면 마커를 늘리는 쪽을 N5 와 함께 검토 |
| **N13** | 🟡 **마커 중심은 코너 평균이 아니다** — 사영변환은 중점을 보존하지 않는다. 45°·400mm 합성에서 코너 평균은 정답에서 **2.25px** 어긋나고 대각선 교점은 **0.31px** 이다(**7.2배**). 작업면으로 치면 약 2mm 대 0.3mm. `marker_center` 는 교점으로 푼다 |
| **N14** | 🟡 **먼 거리에서 검출이 깨지기 시작한다** — 800mm·640×480 합성에서 **3/4** 만 검출됐다. 4개가 최소이므로(N10) 그 조건은 즉시 실패다. 기둥 거리·해상도를 정할 때의 하한 근거 |
| **N11** | 🟡 **DLT 만으로는 잔차가 계통적으로 크다** — DLT 가 최소화하는 것은 대수 오차이고 우리가 판정에 쓰는 값은 mm 재투영 오차다. 둘이 달라서 DLT 해는 mm 기준으로 약간 열세다(합성 200회 **전부**, 0.1718mm 대비 +1.0e-3mm). `solve_homography` 에 가우스-뉴턴 정련을 붙여 해소했고, `cv2.findHomography(method=0)` 와 RMS 동률(차이 2.2e-5mm)까지 맞췄다. **cv2 도 같은 이유로 DLT 뒤 LM 을 돌린다** |
| **N12** | 🟡 **기둥 회전 민감도는 어림보다 크다** — 0.1° → 작업면 **0.932mm**(어림 0.7mm), 0.5° → 4.659mm. 종이 네 귀퉁이 기준 최대 변위, 합성 실측. 상세는 [`cal_readme.md`](cal_readme.md) §1 진동 |
| **N8** | 🟡 손목 기울임 확장 | 수직 고정이 성공하면 기울여 그리는 쪽으로 확장 예정. 그때는 **펜 TCP 캘리브레이션이 되살아난다** (자세마다 펜 끝이 바뀌므로) |

### 3.5 설계 원칙

- **수집과 계산을 분리한다** — 임계(N4)가 미정인데 붙여 놓으면 임계를 바꿀 때마다 로봇을 다시 돌려야 한다.
  원자료를 먼저 떨구고 `--recompute` 로 계산만 다시 돈다
- **표본 원자료를 남긴다** — 프레임·터치 점을 지우지 않는다
- **좌표 규약 변환은 한 군데서만** — OpenCV 표현과 로봇 규약이 만나는 지점을 `cal_geometry.py` 로 몬다
- **`H` 는 저장값이 아니라 매번 푸는 값** — 진동에 대한 방어가 구조에서 나온다
- **검출 실패는 예외가 아니라 값** — 가림·조명 문제를 조용히 넘기면 적은 점으로 `H` 가 풀려 정밀도가 말없이 떨어진다
- **로봇을 움직이는 함수는 `--dry-run` 을 먼저 통과한다** — `movej.md` §2.3 관례

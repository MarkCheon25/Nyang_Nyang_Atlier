## 1. 개요

### 이 셋업이 캘리브레이션을 단순하게 만든다

카메라가 고정이고, 그림이 **평면 위에서만** 일어나고, 로봇이 그 평면 위 점을 펜으로 짚을 수 있다.
세 조건이 다 서면 카메라 모델을 통째로 건너뛸 수 있다.

```
교과서 경로:  이미지 → (intrinsic) → 정규화좌표 → (solvePnP) → T_cam→board → T_base→cam → base
                       ↑ 카메라 내부를 알아야 각 단계가 성립

이 경로   :  이미지 픽셀 (u,v) ──────── H (3×3) ────────→ base 평면 (x, y)
                       ↑ 중간 단계가 없다. 대응점 4쌍 이상이면 H 가 풀린다
```

펜으로 작업면 위 점을 짚고 같은 점을 카메라로 본다. 대응쌍이 쌓이면 **`H` 하나가 직접 나온다.**
`K` 도, 왜곡계수도, `T_base→cam` 도 구하지 않는다 — 전부 `H` 안에 녹는다.

**딸려오는 결과 두 가지**

- **펜 TCP 캘리브레이션이 필요 없다.** 손목 자세가 고정이면 펜 끝과 flange 는 상수 오프셋만 다르고,
  `H` 를 flange 기준으로 뽑으면 그 오프셋이 흡수된다.

  > 📌 **2026-08-16 — L14 가 닫혔다.** 병렬 세션(`260816-알트도르퍼`)이 펜홀더 TCP 를 실기 4점법으로
  > 실측해 컨트롤러에 등록했다: **(-3.675, -1.725, 120.560) mm**. "우회한다"는 표현은 이제 맞지 않는다 —
  > 우회할 문제가 사라졌다. 그래도 **결론은 그대로** flange 기준이다: `H` 가 상수 오프셋을 흡수하므로
  > tcp 를 알아도 식이 간단해지지 않고, 등록값은 컨트롤러 소유라 세션 밖에서 바뀔 수 있다.
  > 편심 xy 는 좌표계 회전이 미확정이라 아직 방향을 못 믿는다.
- **평면과 `H` 가 같은 데이터에서 나온다.** 짚을 때 `x, y, z` 가 다 기록되므로, 한 번의 터치 루틴으로 둘 다 얻는다

### 진동을 문제에서 없애는 구조

기둥은 **생각보다 훨씬 민감하다.** 400mm 거리·1280폭에서 이미지 1px 이 작업면 약 **0.6mm**,
45도 경사를 감안하면 **약 0.9mm** 다. 회전은 더해서 — **기둥이 0.1° 돌면 작업면에서 0.9mm 가 밀린다.**

> 📌 이 회전 수치는 **합성으로 실측했다** (`cal_geometry_test.py`, 2026-08-16). 종이 네 귀퉁이
> 기준 최대 변위로 **0.1° → 0.932mm · 0.5° → 4.659mm**. 각도에 거의 비례한다.
> 처음 어림했던 0.7mm 보다 **크다** — 어림은 거리만 봤고, 실제로는 45도 경사가 한 축을
> 늘려 놓기 때문이다. 즉 기둥은 어림보다 더 민감하다.

그래서 `H` 를 **한 번 구해 저장하는 값이 아니라 매 작업 전에 다시 푸는 값**으로 둔다(블록 C).
마커의 base 좌표만 고정이면 카메라가 어디로 움직였든 상관없다. 로봇 터치는 최초 1회로 끝난다.

방어가 *"잘 조여두기"* 에서 **"움직여도 무관한 구조"** 로 바뀐다.
그래도 드리프트는 **보고한다** — 자동 보정되더라도 기둥이 움직였다는 사실 자체가 점검 신호다.

### 펜업·다운은 깊이 문제가 아니다

카메라가 판단하지 않는다. **로봇 z 명령**이다.

```
평면을 로봇 터치로 확정  →  z_paper (base 좌표)
펜 다운  =  z_paper − δ    (δ ≈ 0.5~1mm, 볼펜이 파고드는 깊이)
펜 업    =  z_paper + h    (h ≈ 3~5mm)
```

> 🔴 **2026-08-16 — 여유가 생각보다 없다.** 펜홀더 스프링 **행정이 1.069mm 뿐**이라고 실측됐다
> (`260816-알트도르퍼`). TCP 가 스프링 **자유 길이** 기준으로 등록돼 있어 *지령면 아래로 파고든 mm =
> 스프링 압축량 = 필압* 이 그대로 성립한다. 즉 δ 는 이제 **재는 값이 아니라 고르는 값**이다.
> 다만 **δ + 작업평면 오차 < 1.069mm** 를 넘기면 스프링이 바닥나 펜이 종이를 긁는다.
> 그래서 작업평면 z 정확도 요구가 **±0.4mm** 로 못박혔다 — 블록 B 평면 잔차 임계의 첫 실물 근거다(N4).

depth 를 안 받는 이유이기도 하다 — D456 의 depth 는 IR 스테레오라 **텍스처가 필요한데 흰 A4 는 무늬가 없고**,
45도 경사면에서 오차가 mm 단위로 뜬다. 로봇 반복정밀도(±0.1mm)가 한 자릿수 이상 정확하다.

### 기준 마커 배치

```
        ┌─────────────────────────────────┐
        │  [M0]                     [M1]  │   마커 4개는 종이 바깥
        │        ┌───────────────┐        │   → 종이가 절대 안 가림
        │        │   A4 종이     │        │   → 종이 영역이 내삽 구간에 들어가
        │        │   (그림)      │        │     정확도가 가장 좋다
        │        └───────────────┘        │
        │  [M2]                     [M3]  │
        └─────────────────────────────────┘
                   작업대 상면
```

- 딕셔너리 **`DICT_4X4_50`**, 기준 마커 ID **`0~3`**. 종이 지그용은 **`40~`** 으로 대역을 가른다
- 마커 크기 **50mm** — 45도·400mm 에서 셀당 약 9px 로 여유가 크다
- A4 한 장에 4개 + 재단선으로 인쇄해 잘라 붙인다
- 🔴 **작업면에 평평하게** 붙일 것. 들뜨면 그 오차가 그대로 `H` 에 들어간다

## 3. 실행

명령 구성과 각 명령이 요구하는 선행 조건은 [`cal_script.md`](cal_script.md) §3.1 에 있다.
🚧 블록 B~E 는 미구현이라 `NotImplementedError` 로 끝난다 — 아래는 **블록 A** 뿐이다.

### 3.1 기준 마커 시트 뽑기 (블록 A)

```bash
cd src/drivers/cam_comm/calibration
python3 cal.py board                    # 기준 마커 4개 시트 → data/board/marker_sheet.pdf
python3 cal.py board --kind charuco     # ChArUco 보드 (블록 A ④ 로 갈 때만)
python3 cal.py board --dry-run          # 파일을 안 쓰고 치수만 보고
python3 cal.py board -o /경로/시트.pdf   # 출력 위치 지정
```

출력 예 — **명목값이 아니라 실제 렌더 치수를 찍는다:**

```
[A] 기준 마커 시트  DICT_4X4_50  ids 0, 1, 2, 3
    명목 50.000mm → 렌더 50.038mm @ 600dpi (셀 배수 반올림, +0.076%)
    quiet zone 10mm
    → .../data/board/marker_sheet.pdf  (49 KB)
```

> 🔴 **렌더 치수는 명목 치수와 같지 않다.** 마커 한 변은 셀 수(4X4 → 테두리 포함 **6**)의 배수
> 픽셀이어야 셀 경계가 정수로 떨어진다. 600dpi·50mm 는 1181.10px 라 **1182px = 50.0380mm** 로
> 반올림된다. 아니면 셀이 197/196px 로 불균등해져 코너가 최대 0.5px 어긋난다.
> **그래도 설정에 넣을 값은 인쇄물 실측값이다** — 렌더 오차 위에 프린터 배율 오차가 또 얹힌다.

### 3.2 인쇄 · 부착

1. **100% 배율로 인쇄한다.** "페이지에 맞춤"·"큰 페이지 축소"를 끈다
2. **자르기 전에 시트의 스케일 바를 자로 잰다.** 100.0mm 가 아니면 그 시트는 버린다
3. 재단선을 따라 자른다. **이름표 띠가 아래로** 오게 둔다 — 위쪽 변에 삼각형 3개가 찍혀 있다
4. 작업면에 **평평하게** 붙인다. 배치는 §1 "기준 마커 배치" — M0·M1 위, M2·M3 아래, 종이 바깥
5. 인쇄된 마커 한 변을 재서 `markers.size_mm` 에 그 실측값을 넣는다

### 3.3 설정 바꾸기

기본값만으로 돌아간다. 바꾸려면 이 폴더에 `cal_config.yaml` 을 두거나 `--config` 로 지정한다.
키 목록의 정본은 [`cal_config.py`](cal_config.py) `default_config()`.

```yaml
markers:
  size_mm: 50.31        # ← 인쇄물을 자로 잰 값
board:
  dpi: 600
  scale_bar_mm: 100.0
```

`validate_config()` 가 **반쯤 맞는 설정을 즉시 막는다** — quiet zone 이 1셀보다 작거나,
타일이 페이지를 넘거나, ChArUco 딕셔너리가 기준 마커와 같으면(ID 충돌) 거기서 멈춘다.

### 3.4 카메라 없이 확인하는 법

카메라가 오기 전에도 **인쇄물이 쓸 만한지**는 잴 수 있다. 04pc 에서 실제로 돌린 것:

| 확인 | 방법 | 04pc 결과 (2026-08-16) |
|---|---|---|
| 생성물이 검출되는가 | PDF 를 `pdftoppm` 으로 되렌더 → `detectMarkers` | 600·300·**150dpi** 전부 4/4 |
| 실치수가 맞는가 | 검출 코너의 변 길이를 mm 로 환산 | 50.017 / 49.975 / 49.953mm (렌더 50.038) |
| PDF 배율이 맞는가 | `pdfinfo` MediaBox | 210.016 × 297.011mm (A4 인식) |

- **서브픽셀 정련이 잔차를 1.8~2.9배 줄인다** — `refine_corners_subpixel()` 을 선택이 아니라
  기본으로 둘 근거다. 경사가 얕을수록(20도) 이득이 작다(1.1배)
- **경사각이 거리보다 중요하다** — 45도가 20도보다 2배 이상 낫고, 600mm 로 물러서도 45도면 45도 400mm 보다 낫다.
  대신 1px 이 덮는 면적이 0.63→0.94mm 로 커져 **분해능은 나빠진다**
- ⚠️ **시야의 상당 부분이 종이 밖이다** — `sim_view.png` 에서 A4 는 화면 폭의 **약 35%** 만 차지한다.
  마커가 종이 **바깥**에 있어 시야를 마커에 맞춰야 하고, 그만큼 종이가 작게 잡힌다.
  마커를 종이에 더 붙이면 분해능은 올라가지만 종이가 마커를 가릴 위험이 생긴다 — 배치 확정(블록 B) 때 저울질할 것
- 🔴 **이 표는 인쇄물과 검출 알고리즘의 상한이다.** 렌즈 왜곡·마커 들뜸·조명·로봇 반복도가 빠져 있다 —
  실기 정확도는 블록 E 가 잰다

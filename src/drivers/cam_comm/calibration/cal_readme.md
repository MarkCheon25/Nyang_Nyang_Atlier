여기서 벗어나면 아래 설계가 통째로 무효가 되므로 먼저 적는다.

| 전제 | 내용 |
|---|---|
| **eye-to-hand** | 카메라는 **기둥에 고정**이고 로봇과 함께 움직이지 않는다. 로봇암 장착은 시도했으나 여의치 않았다 (2026-08-16) |

## 1. 개요

### 이 셋업이 캘리브레이션을 단순하게 만든다

카메라가 고정이고, 그림이 **평면 위에서만** 일어나고, 로봇이 그 평면 위 점을 펜으로 짚을 수 있다.
세 조건이 다 서면 카메라 모델을 통째로 건너뛸 수 있다.

```
교과서 경로:  이미지 → (intrinsic) → 정규화좌표 → (solvePnP) → T_cam→board → T_base→cam → base
                       ↑ 카메라 내부를 알아야 각 단계가 성립

이 경로   :  이미지 픽셀 (u,v) ──────── H (3×3) ────────→ base 평면 (x, y)
                       ↑ 중간 단계가 없다. 대응점 4쌍 이상이면 H 가 풀린다
```

펜으로 작업면 위 점을 짚고 같은 점을 카메라로 본다. 대응쌍이 쌓이면 **`H` 하나가 직접 나온다.**
`K` 도, 왜곡계수도, `T_base→cam` 도 구하지 않는다 — 전부 `H` 안에 녹는다.

**딸려오는 결과 두 가지**

- **펜 TCP 캘리브레이션이 필요 없다.** 손목 자세가 고정이면 펜 끝과 flange 는 상수 오프셋만 다르고,
  `H` 를 flange 기준으로 뽑으면 그 오프셋이 흡수된다. 업무목록 **L14**(TCP 오프셋이 세션마다 바뀜)도 우회된다
- **평면과 `H` 가 같은 데이터에서 나온다.** 짚을 때 `x, y, z` 가 다 기록되므로, 한 번의 터치 루틴으로 둘 다 얻는다

### 주요 기능

| # | 블록 | 하는 일 | 주기 | 카메라 | 로봇 | 산출물 |
|---|---|---|---|---|---|---|
| **A** | 인쇄물·왜곡 점검 | 기준 마커 시트 생성 · 공장 intrinsic 읽기 · 직선 테스트 | 최초 1회 | 일부 | — | `distortion.yaml` |
| **B** | 기준 확정 | 마커를 펜으로 짚어 base 좌표 확정 + 작업평면 산출 | **최초 1회** | ✅ | ✅ | `reference.yaml` |
| **C** | **`H` 갱신** | 마커 촬영 → `H` 재계산 → 드리프트 판정 | **매 작업 전** | ✅ | — | `homography.yaml` |
| **D** | 종이 위치 인식 | 종이를 찾아 base 좌표로. 대충 놓아도 되게 만든다 | 매 작업 | ✅ | — | `paper.yaml` |
| **E** | 검증 | 알려진 점 재현성·왕복 오차·반복 촬영 흔들림 | 수시 | ✅ | ✅ | 리포트 |

### 진동을 문제에서 없애는 구조

기둥은 **생각보다 훨씬 민감하다.** 400mm 거리·1280폭에서 이미지 1px 이 작업면 약 **0.6mm**,
45도 경사를 감안하면 **약 0.9mm** 다. 회전은 더해서 — **기둥이 0.1° 기울면 작업면에서 0.7mm 가 밀린다.**

그래서 `H` 를 **한 번 구해 저장하는 값이 아니라 매 작업 전에 다시 푸는 값**으로 둔다(블록 C).
마커의 base 좌표만 고정이면 카메라가 어디로 움직였든 상관없다. 로봇 터치는 최초 1회로 끝난다.

방어가 *"잘 조여두기"* 에서 **"움직여도 무관한 구조"** 로 바뀐다.
그래도 드리프트는 **보고한다** — 자동 보정되더라도 기둥이 움직였다는 사실 자체가 점검 신호다.

### 펜업·다운은 깊이 문제가 아니다

카메라가 판단하지 않는다. **로봇 z 명령**이다.

```
평면을 로봇 터치로 확정  →  z_paper (base 좌표)
펜 다운  =  z_paper − δ    (δ ≈ 0.5~1mm, 볼펜이 파고드는 깊이)
펜 업    =  z_paper + h    (h ≈ 3~5mm)
```

depth 를 안 받는 이유이기도 하다 — D456 의 depth 는 IR 스테레오라 **텍스처가 필요한데 흰 A4 는 무늬가 없고**,
45도 경사면에서 오차가 mm 단위로 뜬다. 로봇 반복정밀도(±0.1mm)가 한 자릿수 이상 정확하다.

### 기준 마커 배치

```
        ┌─────────────────────────────────┐
        │  [M0]                     [M1]  │   마커 4개는 종이 바깥
        │        ┌───────────────┐        │   → 종이가 절대 안 가림
        │        │   A4 종이     │        │   → 종이 영역이 내삽 구간에 들어가
        │        │   (그림)      │        │     정확도가 가장 좋다
        │        └───────────────┘        │
        │  [M2]                     [M3]  │
        └─────────────────────────────────┘
                   작업대 상면
```

- 딕셔너리 **`DICT_4X4_50`**, 기준 마커 ID **`0~3`**. 종이 지그용은 **`40~`** 으로 대역을 가른다
- 마커 크기 **50mm** — 45도·400mm 에서 셀당 약 9px 로 여유가 크다
- A4 한 장에 4개 + 재단선으로 인쇄해 잘라 붙인다
- 🔴 **작업면에 평평하게** 붙일 것. 들뜨면 그 오차가 그대로 `H` 에 들어간다

## 2. 설치

실행 환경 요건이다. 🚧 확정되는 대로 버전을 박는다.

| 구분 | 요건 | 상태 |
|---|---|---|
| 카메라 | Intel RealSense **D456** — 스톡 `uvcvideo` 로 충분, DKMS 금지 | 확인됨 ([`RealSense_D456.md`](../RealSense_D456.md)) |
| 해상도 | **1280×800** 권장 — 45도 경사가 유효 해상도를 0.71배로 깎는다. USB2 면 15fps 지만 정지 촬영이라 무관 | 확인됨 |
| 설치 거리 | 카메라–작업면 **400mm 이내** 권장. 600mm 는 45도에서 셀당 3px 로 검출이 불안정하다 | 🔴 미측정 |
| 마커 | `DICT_4X4_50` · 50mm · ID 0~3 · A4 인쇄 후 재단 | 🚧 인쇄 전 |
| Python | `numpy` · OpenCV `cv2` + contrib(`cv2.aruco`) · `pyrealsense2`(공장 intrinsic 조회용) | 🚧 미확정 |
| 로봇 통신 | 컨트롤러 MQTT 직결 — [`hcr5_comm/tools/mqtt_cmd.py`](../../hcr5_comm/tools/mqtt_cmd.py) `query_pos()` 재사용 | 확인됨 |
| 실행 위치 | 호스트 / 컨테이너 중 어디서 도는지 | 🔴 미정 |

> 🔴 **인쇄 함정** — 프린터의 "페이지에 맞춤"이 켜져 있으면 실제 치수가 몇 % 달라지고,
> 그 오차가 `H` 에 **스케일 오차로 그대로 박힌다.** 100% 배율로 인쇄하고,
> 인쇄물의 스케일 바를 자로 재서 설정에 실측값을 넣을 것.

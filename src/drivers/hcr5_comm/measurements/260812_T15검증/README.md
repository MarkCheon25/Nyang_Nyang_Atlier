## 이 세션이 새로 알아낸 것 — 측정량 정의 3건

문서 수치는 전부 재현됐다. 어긋난 것은 없고, **어떻게 재야 그 수치가 나오는지**가 셋 드러났다.
전부 `검증.md` 기재(검D) 때 실측 칸에 같이 들어가야 한다.

1. **V-9 의 측정량은 플러그인 자체 값이다.** 로그의 `상태 수신 중단(1016ms > 1000ms)` 이 기준 대상이고,
   `nmcli` 명령 시각부터 재면 **1287.6ms** 로 **기준(1.0±0.2s)을 벗어난다** — 인터페이스 teardown 지연이 섞이기 때문.
   버스바의 1028ms 도 플러그인 자체 값이다(원본 로그로 확인). **재는 자리를 안 맞추면 정상 거동이 실패로 잡힌다.**
2. **V-6 의 손실통계는 `statistics/full` 에 없다.** `LoanedStateInterface` 가 **파괴될 때** 런치 로그에
   WARN 으로 한 번 찍힌다 → **V-9(두절)나 정상 종료를 태워야 나온다.** 읽기 창을 닫는 순서가 곧 측정 순서다.
3. **V-11 을 `--ros-args -p robot_description:=<URDF>` 로 재면 안 된다.** XML 이 인자 파서를 깨뜨려
   (`Failed to parse global arguments`) 노드가 아예 안 뜬다. `controller_manager` 는 **`/robot_description` 토픽을
   구독**하므로 노드를 먼저 띄우고 **transient_local 로 발행**해야 한다.

### 곁가지 (기준 밖 · 기록만)

- **V-6 의 낡은 문면이 왜 못 쓰는지가 실측됐다** — 로봇 정지 시 `/joint_states` 발행률 **100.000Hz** ·
  **값 갱신 0.000Hz**(30초·2999표본, 변화 0회). 낡은 기준 *"값 갱신 30±3Hz"* 는 **정상 거동을 0 으로 채점**한다.
  단자대의 13.45Hz 는 로봇이 **움직이는 중**의 값이라 서로 모순이 아니다.
- **결함 ③ 이 재확인됐다** — `allow_motion=false` 인데 V-9 의 `on_error` 가 `move/stop` 을 발행했다
  (로그: *"에러 — move/stop 발행·발행 영구 잠금"*). *"읽기 전용 = 실기 무발행"* 이 아니다.
- **결함 ① 수정이 실기에서 다시 확인됐다** — `configure`→`activate` 성공까지 **86ms**, 최초 기동 1/1 성공.
- **축온** 시작 53/51/53/54/54/54°C → 종료 53/51/53/54/54/55°C = **실질 +0**.
  서보 OFF·`power=0` 이라 **B 는 발열을 안 쓴다**는 전제가 이 PC 에서도 실측됐다(버스바 재확인).
  ⚠️ 다만 **착수 시점 축온이 게이트(≤50°C)를 넘긴 54°C 였다** — 우리 열이 아니라 실온 평형으로 보인다(가설).
  **Rokey6 판정으로 서보 OFF 근거로 진행**했다. 서보 ON 세션(검C1·검C2)에는 이 판정이 **적용되지 않는다.**

# 검C2 — 서보 ON 창② (2026-08-12, 04pc · 260812-쇼크업소버) · **미완**

계획서 `briefs/검증_재현_세션분할.md` §2 의 **검C2** = `allow_motion:=true` 로 쓰기 **5행**
(V-7·V-13·V-14·V-15·V-5). **창을 열지 못했다** — 착수 직전에 **실기 드라이브가 내려갔다.**

여기 있는 것은 그 사정의 원자료와, **다음 세션이 창을 바로 열 수 있도록 준비된 절차**다.
실측·경위의 원본은 루트 `실기PC_작업기록.md` 260812-쇼크업소버 절.

## 왜 못 열었나 (사실)

| 시각 | `controllerStatus` | 축온 | voltage | 관절값 |
|---|---|---|---|---|
| 11:51:36 (착수 게이트) | `CONNECTED` | 52~55°C | **48V** | base `0.0026°` … 실제 자세 |
| 12:15:03 (스택 기동) | **`DISCONNECTED`** | — | — | — |
| 13:2x (진단) | **`DISCONNECTED`** | 6축 **`-1`** | **`-1V`** | 6축 **`0`** · 293표본 변화 **0** |
| 13:5x (소프트 리셋 후) | **`TRYING_CONNECTION`** | 〃 | 〃 | 〃 |

- **컨트롤러 PC·브로커·상태버스는 정상이다** — `motion/joint/position` **29.28Hz**, heartbeat·IO 모니터 4종 발행 중.
  끊긴 것은 **컨트롤러↔드라이브(필드버스)** 구간이다.
- ⚠️ **지금 나오는 관절값 `0` 은 로봇이 영점에 있다는 뜻이 아니다** — 데이터 원천이 죽은 것이다.
  팔의 실제 자세는 이 버스로 알 수 없다.
- 버스에 **사유가 안 실렸다** — `event/button`(e-stop)·에러 이벤트 **0건**.
- **소프트 리셋 2종의 효력** (Rokey6 승인 후 시도, 서보 OFF·무전원이라 움직일 것이 없는 상태) —
  `error/reset` **ack success·상태 불변** / `controller/system/reset` **ack success → `DISCONNECTED` → `TRYING_CONNECTION`**.
  ★ `FIELD_BUS_SW_STATE_TRYING_CONNECTION` 은 **기존 문서에 없던 세 번째 상태**이고, 이 명령이 그 전이를 일으킨다는 것도 처음 관측됐다.
  4분 관찰에도 드라이브 무응답 → **물리 점검이 선행**(e-stop · 제어박스 전원 · 펜던트 에러 표시 · 본체 케이블).

## 실패한 기동이 남긴 재현 증거 3건 — `logs/C2_launch.log`

창은 못 열었지만 이 로그가 **실기에서** 세 가지를 다시 보여 준다.

| # | 무엇 | 로그 |
|---|---|---|
| 1 | **결함 ① 수정이 동작한다** | `on_activate` 가 **500ms 대기 후** 사유를 명시하고 ERROR (`필드버스가 … 아니다 (500ms 대기, 현재 'FIELD_BUS_SW_STATE_DISCONNECTED')`). 수정 전이라면 즉시 실패하며 자기모순 메시지를 냈을 자리다 |
| 2 | **V-12 대조군 거동** | 완화책 없이 기동하면 `terminate` → `Stack trace` → `Aborted`(exit −6). 검B 가 자립시킨 대조군과 같은 거동이 **실기 앞에서** 재현됐다 |
| 3 | **결함 ③** | `allow_motion=true` 인데 **에러 경로가 `move/stop` 을 발행**했다 (`에러 — move/stop 발행·발행 영구 잠금`). 게이트 밖 발행은 잠금 값과 무관하다 |

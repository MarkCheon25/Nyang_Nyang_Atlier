# A4 작업평면 네 모서리 — 2026-08-17 (03pc · 260816-브론치노)

Mark 가 실기로 A4 용지의 네 모서리를 펜 끝으로 짚고 자세를 읽어, **moveit2 동료(ysh)에게 직접 전달**한 값이다.
그 뒤로 원본은 03pc 세션 장부(업무목록 **L38**)에만 있었다 — 2026-10-04 에 여기로 옮겼다(세션 261004-데키리코).

## 평면 적합

최소제곱 평면(`n·p = d`, `n_z > 0`). 2026-10-04 에 다시 계산해 같은 값을 얻었다.

```
n = (+0.028396, +0.000442, +0.999597)    d = −0.0755
z(x,y) = −0.0755 − 0.028407·x − 0.000442·y        [mm]
```

- 🔴 **작업면이 1.627° 기울었다** — 네 모서리의 z 낙차 **5.93mm** 는 펜홀더 스프링 행정 **1.069mm**(`260816_펜TCP`)의 **5.5배**다.
  **고정 z 로는 종이 전면을 그릴 수 없다**
- 기울기는 거의 전부 **x 방향**이다 (법선 y 성분 4.4e−4)
- 원인(테이블·매트 경사 vs 로봇 기구 오차)은 **미판정**. 평면식이 베이스 좌표라 원인과 무관하게 쓸 수 있다

⚠️ **잔차 RMS 0.0077mm 는 평탄성의 증거가 아니다** — 4점에 평면 3모수라 **자유도가 1**이다.
네 모서리가 한 평면과 모순되지 않는다는 것뿐, 종이 **안쪽**의 배부름·말림은 아무 말도 못 한다. 중앙 1점이 진짜 시험이다.
(`260816_펜TCP` 의 *"잔차가 작은 것이 품질의 증거가 아니다"* 와 같은 함정)

## 이 값을 쓰는 곳 — 인계 위험

| 어디 | 어떻게 |
|---|---|
| ysh `hcr5_examples/include/hcr5_examples/a4_paper.hpp:70-73` (브랜치 `ysh_moveit_ros2_control`) | 네 모서리를 **m 단위 상수로 하드코딩**한다. 기본값은 z 를 `z_left −0.012` · `z_right −0.014` 로 **덮어쓴다**(`use_measured_z:=false`) — ysh 주석 스스로 *"우변에서 펜이 종이보다 4.3mm 떠서 그 영역은 아예 안 그려진다"* 고 적는다 |
| `hcr5_bridge` `stroke` | 아직 이 평면을 안 쓴다 — 상수 `--z` 다 ([`stroke.md`](../../../hcr5_bridge/stroke.md) §4) |

🔴 **누가 언제 이 하드코딩을 버리는지 정해지지 않았다.** 캘리브레이션(F5)이 붙는 순간 종이 위치는
블록 D 가 주는 값으로 갈아타야 한다. 안 갈아타면 **종이를 옮긴 순간 조용히 어긋난다** —
`src/moveit2/docs/Vision Interface Contract.md` §2.2 (브랜치 `g0ranii/drawing_cat`)가 예고한 자리다.

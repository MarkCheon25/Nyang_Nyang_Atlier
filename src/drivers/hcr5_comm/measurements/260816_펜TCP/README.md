## 1. 왜 4점법인가 — 무엇을 푸는 것인가

같은 물리적 한 점을 **자세를 바꿔가며** 펜 끝으로 짚는다. 자세 `i` 에 대해

```
p_flange(i) + R(i)·t = P          t = 구하려는 TCP 오프셋(3) · P = 그 고정점(3)
```

미지수 6개, 자세 하나가 방정식 3개. 자세 3개면 풀린다.

### 🔴 핵심 함정 — **점 개수가 아니라 자세 다양성**이 조건수를 정한다

**J6(툴축)을 안 돌리면 `t` 의 xy 성분이 `P` 와 완전히 축퇴한다.** 최소제곱이 조준 오차를
가짜 편심으로 흡수해 버리고, 잔차는 작게 나온다 — *잔차가 작다는 것이 품질의 증거가 아니다.*
(자세 3개면 자유도가 3뿐이라 과적합이다.)

이번 세션이 정확히 여기 당했다. 펜던트 4점법이 **z 는 맞히고 xy 는 틀렸다.**
그리고 J6 를 78.5° 만 흔든 데이터로 *"편심은 허상"* 이라 판단해 xy 를 0 으로 만든 것이
**더 나쁜 등록**을 낳았다(§3 검산B). J6 를 153°·277°·329° 로 넓히자 편심이 실재로 확정됐다.

📌 **다음에 4점법을 할 사람에게** — 펜던트가 점 10개를 요구해도 개수를 채우는 게 목적이 아니다.
**J6 를 최소 3값, 되도록 300° 이상 벌려서** 짚어라. J3·J4 만 흔든 점을 10개 모아도 xy 는 안 나온다.

## 2. 계측기 — 전부 **로봇을 안 움직인다**

|---|---|

### `tool_probe.py` — 정지 상태로 등록값을 읽는 법

읽기·질의 토픽이 **없다**. `robot/setup/tcp` 는 쓰기 전용이다. 그런데 FK RPC 가 길을 열어 준다:

> **`robot/convertPose` 는 `poseType` 을 `"tcp"` / `"flange"` 둘 다 받는다** (2026-08-16 확인, 신규 사실)

같은 관절각으로 두 번 부르면 컨트롤러가 *툴을 적용한 결과*와 *안 한 결과*를 나란히 준다.
차이를 플랜지 회전으로 벗기면 자세 무관 상수가 된다:

```
t = R_flange^T · (p_tcp − p_flange)
```

회전 규약은 **ZYX `R = Rz(rz)·Ry(ry)·Rx(rx)`** — 업무목록 L16 확정(잔차 6.9e-16).
이 방법이 성립하는 것 자체가 검증된다: 등록 전 `t=(0,0,0)`, 등록 후 정확히 넣은 값이 나왔다.

```bash
python3 ../../tools/tool_probe.py                    # 지금 등록된 툴
python3 tcp_point.py add 검산D                        # 펜 끝을 맞춰 놓고 한 점
python3 tcp_point.py spread 검산D                     # 산포 판정
python3 solve_tcp.py 검산D -3.675 -1.725 119.491      # 참값 역산
python3 tcp_point.py stroke 표면_압축2 표면_자유2      # 스프링 행정
```

## 3. 회차 기록 — 등록값이 다섯 번 바뀌었다

### 등록 이력

| 시점 | `TCP_POSITION_XYZ` | \|t\| | 비고 |
|---|---|---|---|
| 기준선 | `(0, 0, 0)` | 0 | 활성 툴 없음. L14 가 적던 `tool1` 128.05mm 는 **이미 사라진 상태**였다 |
| 펜던트 4점법 | `(−1.410, −4.270, 120.300)` | 120.384 | z 는 맞고 xy 가 틀렸다 (J6 축퇴) |
| xy → 0 | `(0, 0, 120.300)` | 120.300 | 🔴 **내 오판.** 검산이 더 나빠졌다 |
| 수동 입력 | `(−3.675, −1.725, 119.491)` | 119.560 | 검산C 역산값. 펜던트보다 나은 등록 |
| **최종** | `(−3.675, −1.725, 120.560)` | **120.628** | 위 + 행정 1.069mm = 자유 길이 |

### 검산 이력 — 같은 점을 여러 자세로 짚어 tcp 좌표가 얼마나 흩어지나

| 회차 | J6 폭 | RMS | 최악 | 판정 |
|---|---|---|---|---|
| 검산A 그룹1 | 0.01° (고정) | 1.196 | 1.708 | 편심을 **검증 못 하는** 데이터였다 |
| 검산A 그룹2 | 78.5° | 2.471 | 3.442 | |
| 검산B | 153° | 3.276 | 4.002 | xy 를 0 으로 만든 뒤 — **더 나빠졌다** |
| 검산C | 277° | 4.209 | 4.942 | ⚠️ 재티칭이 **'적용' 안 눌려** 값이 안 바뀐 회차 (§5 함정) |
| **검산D** | **329°** | **1.399** | **1.894** | ✅ 최종 등록으로 **2.6배 개선** |

### 조준 반복도 = **1.041 mm** — 이것이 잡음 바닥이다

검산A #7 vs #8: J6 는 같고 J3 가 32°, J4 가 60° 다른 두 자세. 등록이 완벽해도 이만큼은 흩어진다.
**사람이 눈으로 펜 끝을 한 점에 맞추는 정밀도**이고, 위 표의 모든 숫자를 이 바닥에 대고 읽어야 한다.

### 검산D 역산 — 여기서 멈춘 이유

```
d = (−1.365, 0.012, −2.195)      |d|xy = 1.365 mm      적합 잔차 RMS = 1.273 mm
```

남은 오차 `|d|` 가 **잔차와 같은 크기**다. 즉 신호가 잡음 위로 안 올라온다 —
이 데이터로는 더 못 좁힌다. 편심은 실재가 확정됐고(2.9~4.1mm), 값의 정밀도는 조준 한계에 걸렸다.
📌 더 좁히려면 사람 눈이 아닌 **기구적 기준점**(핀·구멍)이 필요하다.

## 4. 스프링 — 행정 **1.069 mm**

펜홀더는 필압용 스프링식이다. **축 방향으로만** 작용하므로 z 는 흔들고 xy 는 안 흔든다
(세션 중 네 번 확인). 그래서 편심 판정과 스프링은 서로 간섭하지 않는다.

같은 표면을 압축 상태 / 자유 상태로 짚은 z 차이:

```
압축 tcp.z = −21.434      자유 tcp.z = −20.365      ★ 행정 = 1.069 mm
flange z: 98.446 → 99.139  (+0.693mm — 로봇이 실제로 올라갔다)
```

- **등록은 자유 길이**로 한다 → 파고든 깊이가 곧 필압
- **측정은 완전 압축**으로 한다 → 솔리드 하이트에서 강체라 재현된다.
  (스프링이 약해도 문제가 안 되는 이유가 이것이다. 약한 것은 *부분* 압축에서만 문제다)

### 🔴 행정 1.07mm 는 짧다 — BRD R2 에 되먹임된다

BRD R2 는 *"필압 문제 시 스프링 펜홀더로 전환"* 을 완화책으로 적는다. 그런데 실측 완충이 1mm 다.

- 종이 높이 캘리브레이션이 **±0.4mm 급**으로 정밀해야 한다
- 아래로 벗어나면 스프링이 바닥나 **강체 충돌**, 위로 벗어나면 **선이 안 그려진다**
- 테이블·종이 평탄도와 로봇 기구학 오차까지 이 1mm 안에 들어와야 한다

**R2 리스크가 스프링으로 크게 완화되지 않았다.** 더 긴 행정의 스프링을 검토할 근거다.

### ⚠️ 미해결 — z 산포가 행정보다 크다

네 회차의 z 추정이 **119.758 / 116.398 / 119.491 / 121.686** 으로 5.3mm 흩어졌다.
세션 중반에 이것을 스프링 압축 변동으로 해석했는데, **행정이 1.07mm 뿐이니 그 설명은 안 선다.**

지금 판단(가설) — 역산에서 **z 는 xy 보다 결정이 나쁘다.** J6 회전은 xy 평면 정보를 직접 주지만
z 는 다른 축의 다양성에만 의존한다. 즉 z 불확실성 ≈ **±2mm** 로 본다.

📌 **그래도 z 는 이 정도로 충분하다** — z 오차는 **종이 높이 캘리브레이션이 흡수한다**
(실제 작화에서 "펜이 닿는 높이"를 실측해 쓰므로 상수 오차는 상쇄된다).
**흡수 안 되는 것은 xy 편심**이다 — 자세를 바꿀 때마다 그림이 왜곡되고 어떤 캘리브레이션으로도 못 없앤다.
그래서 이 세션의 노력은 xy 에 쏠렸다.

## 5. 함정 (겪은 것)

1. **`robot/setup/tcp` 는 '적용' 을 눌러야 나간다** (README §8 함정 2). 펜던트에서 값만 고치고
   화면을 넘기면 컨트롤러는 옛 값 그대로다. 검산C 한 회차를 통째로 날렸다 —
   **재티칭 후 반드시 `tool_probe.py` 로 되읽어 확인할 것.**
2. **읽기 토픽이 없다.** 등록값을 아는 길은 `tool_probe.py` 의 FK 차분 또는
   `get/command/pos` 의 tcp−flange 차이 둘뿐이다.
3. **컨트롤러 재부팅이 호스트의 `hcr5` 이더넷 프로파일을 떨군다** (README §8 함정 4).
   MQTT 가 TimeoutError 로 죽으면 → `nmcli connection up hcr5` (sudo 불필요). 이 세션에 2회.
   ↔ **툴 설정은 재부팅에도 살아남는다**(비휘발성, 2회 확인).
4. **캘리퍼가 없어도 된다.** 로봇 자신이 자다 — `tcp_point.py dist` 로 두 점 거리를 재고
   ISO 표준 치수(카드 85.60×53.98 / A4 297×210 / 동전 26.50·24.00)와 대조한다.
   ⚠️ 다만 이번 세션은 **이 검산 B(알려진 길이)를 못 돌렸다** — 남은 과제다.

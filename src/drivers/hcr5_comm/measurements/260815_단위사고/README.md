# 단위 사고와 한 바퀴 — launch 로그 2건 (2026-08-15, 03pc · 260815-게인즈버러)

운전절차 ④ 에서 joint_1 목표에 `15` 를 넣었더니 **15 rad**(= URDF 859.44° = 실기 769.44°)로 해석돼
명령 속도가 153.9°/s 가 됐고, 실기는 URDF 한계 벽(실기 270°)에서 **267.77°** 에 섰다.
같은 날 URDF 한계를 실기 ±360° 에 맞춘 뒤 base 한 바퀴(0°→280°→360°→0°)를 완주했다.

**경위·처치의 원본은 여기가 아니다** — [`hcr5_bridge/README.md`](../../../hcr5_bridge/README.md)
절 *"넣는 숫자는 URDF 라디안이다"* · §3.8 *"단위 착각이 명령을 폭주시킨다"*, URDF 교정은 커밋 `a9d5f3e`.
이 디렉터리는 **그 사건의 launch 로그 원본**과, 아직 원인을 모르는 `Failed to set value`(03pc 업무목록 **L7**)의 증거를 든다.

두 로그는 `moveit2_dev` 컨테이너의 `/tmp` 에만 있다가 2026-10-04 에 반입됐다(sha256 대조 완료).
launch 로그는 c1·c2 관례대로 **평문**이다.

## `Failed to set value` (L7) — 이 로그가 말하는 것

- **2건이다.** 03pc 업무목록 L7 은 *"로그 1건"* 으로 적었다 — 2026-10-04 정정
- 두 건 다 **목표가 없는 자세 유지 중**에 났다 (13:33:39 완료 → 13:50:39 비활성화, **17분 유지**). 유지 시작 후 7.8분 · 11.6분
- 원인은 **미확인**이다. `is_async=true` 핸들 경합은 당시의 추정일 뿐이다

⚠️ **대조군의 힘이 약하다** — 한 바퀴 창(`launch_한바퀴.log`)은 `Failed to set` **0건**이지만, 그 창에서 목표 없이
유지한 가장 긴 구간은 **65초**(14:15:07 → 14:16:12)다. 사고 창에서 에러가 난 조건(수 분 이상 유지)을 시험하지 않았다.
*"한 바퀴 창에서는 재현 안 됐다"* 는 재현 조건을 갖추지 못한 관측이다.

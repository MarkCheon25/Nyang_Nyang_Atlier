# `mqtt_logger.py` 검증 (2026-08-16, 세션 260816-브뤼헐)

**실기 없이** 돌린 검증이다. 로봇은 전원 OFF 상태였고, 08-11 실캡처를 MQTT 로 되쏘는
재생 브로커(`scripts/replay_broker.py`)로 파이프라인 전체를 태웠다.
도구 설명은 [`../../README.md`](../../README.md) §9 `mqtt_logger.py` 절.

## 1. 재현 방법

```bash
# ① 재생 브로커 (127.0.0.1:18835 에서 대기 → 로거가 붙으면 재생 시작)
python3 scripts/replay_broker.py 18835 ../260811_T15/bus/trace_C.jsonl.gz 1.0 --inject &

# ② 로거 — 회전을 짧은 창에서 보려고 세그먼트·겹침을 압축한다
python3 ../../tools/mqtt_logger.py --host 127.0.0.1 --port 18835 \
        --out /tmp/logger_verify --duration 65 --segment-sec 25 --overlap-sec 5
```

`--inject` 는 재생 도중 인위적 이상 3종을 끼워 넣는다 — 관절 +12° 점프 · 표본 결측 0.5s ·
`error/network` 280002(08-05 드라이브 트립과 같은 형식). **넣지 않으면 실캡처 그대로**라
오탐 확인용으로 쓴다.

## 2. 기준선 — 실캡처에서 뽑은 값 (`trace_C`, 이동 58회 포함)

임계값의 근거다. 감으로 잡은 초판 임계(5°)는 이 분포를 보고 1.0° 로 내렸다.
> ⚠️ **그 1.0° 도 몇 시간 뒤 실기에서 폐기됐다** — 이 캡처가 느린 이동만 담고 있었다. §5 를 볼 것.
> 아래 §3 의 "주입 관절점프" 행들도 **Δ 임계로 잡던 시절의 결과**다(재보정 후 재검증은 §5 표).

| 토픽 | 발행률 | 간격 최대 | 비고 |
|---|---|---|---|
| `motion/joint/position` | 28.9Hz (34.6ms) | 97.5ms | **표본간 관절 최대변화 0.273°** |
| `motion/joint/speed` | 9.74Hz (103ms) | 155ms | 값은 실린다. **단위는 미확정**(T19) |
| `monitor/robot` | 9.74Hz (103ms) | 154ms | 축별 `temp`(°C 정수) |

> `motion/joint/speed` 최대 절대값 2.77 vs 같은 구간 position 차분 최대 8.11°/s — 배율이
> 0.0~3.4 로 널뛰어 **한 상수로 안 맞는다.** 도/s 도 rad/s 도 아니고 지연이나 지령값일
> 가능성이 있다. **튐 진단에는 position 차분이 3배 조밀해 더 낫다.**

## 4. 검증이 잡아낸 결함 4건

전부 이 검증이 없었으면 실기에서 만났을 것들이다.

| # | 결함 | 증상 | 처방 |
|---|---|---|---|
| 1 | 재접속 주기가 5초가 아닌 **4초** | 대기 루프가 누적 `slept` 와 '남은 시간'을 맞비교해 둘이 마주 달리며 절반에서 빠져나왔다 (3초 timeout + 1초 대기) | 목표 시각(`deadline`)을 고정해 비교. 실측 5.00초 |
| 2 | `°/s` 발산 | 표본이 몰려 오면 `dt≈0` 이라 **294337°/s** 가 찍혔다 | `MIN_DT_SEC=5ms` 미만은 버스트로 보고 °/s 미산출, Δ 만으로 soft 판정 |
| 3 | 첫 레코드가 **두 번** 기록 | 원점을 시작 시각으로 옮기자 첫 레코드(`off=0`)가 "앞 겹침" 조건에 걸려 **세그먼트 −1** 에도 쓰였고, 두 파일이 같은 초에 열려 **이름까지 같아졌다** | `k−1 ≥ 0` 조건 + 이름 충돌 시 접미사 |
| 4 | 파일명이 거짓 | 벽시계 epoch 로 잘라 07:22 시작인데 이름이 `030000`(UTC 6시간 경계 = KST 03/09/15/21시). 첫 파일도 6시간을 못 채웠다 | 원점을 **로거 시작 시각**으로, 이름을 **첫 기록 시각**으로 |

> ⚠️ **결함 3 은 초판 불변식 검사를 통과했다.** `1≤len(segs)≤2` 와 수록범위만 봤고
> **`k≥0` 을 안 봤기 때문**이다. 음수 세그먼트도 수록범위 조건은 만족한다.
> 실제로 돌려 파일을 열어보고서야 드러났다 — **불변식만 믿지 말 것.**

### 바꾼 기준 — 가속도(2차 차분)

튐은 *빠른 것*이 아니라 *속도가 불연속으로 꺾이는 것*이다. 같은 38분 실데이터의 가속도 분포:

| p50 | p99 | p99.9 | 최대 | 2000 초과 |
|---|---|---|---|---|
| 0 | 0 | 752 | **1,970 °/s²** | **0건** |

정상 동작은 속도가 매끄럽다 — 분포가 깨끗하게 갈린다. 임계는 그 2배인 **4,000 °/s²**.

### 재보정 후 재검증

| 항목 | 결과 |
|---|---|
| 실기 1차 6.8만 표본 재판정 | ✅ **오탐 51건 → 0건** |
| 기동검증분 재판정 | ✅ 0건 |
| 이동 중(43°/s) 단발 +5° 주입 | ✅ `joint_jump` (4,048 °/s²) |

| 전체 파이프라인(재생 브로커·주입 3종) | ✅ 점프 hard 검출 · 결측 분리 · 에러 원문 · 회전 정상 |

**감도 바닥: 34ms 간격에서 단발 불연속 약 4.6° 이상.** 그 아래는 정상 가감속(최대 1,970°/s²)과
안 갈린다 — 임계를 낮춰서 될 일이 아니라 **원리적으로 겹치는 구간**이다.

⚠️ **이 임계는 63°/s 까지만 돌린 실측에서 나왔다.** 정격(180°/s)에 가깝게 돌리면 정상 가감속도
같이 커져 오탐이 돌아온다. 속도를 크게 올리면 이 절차를 다시 밟아 `--acc-limit` 을 다시 잡을 것.

## 6. 알려진 한계 (도구 자체의 것)

- **REST(4000/8000)로 가는 펜던트 설정 조작은 안 잡힌다** — 버스에 아예 안 실린다(README §8).
  이 로그의 공백이 곧 "조작이 없었다"가 아니다
- **컨트롤러가 죽으면 브로커도 같이 죽어** 그 순간 *이후* 가 안 남는다. 그래서 `_logger/disconnect`
  의 시각 자체가 증거다
- 축온을 **화면에 경고하지 않는다** (조용히 기록만 — Mark 지시). 착수 게이트는 `mqtt_baseline.py`

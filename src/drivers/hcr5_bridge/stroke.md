## 1. 무엇을 하는가

```
ros2 run hcr5_bridge stroke <경로.json> [옵션]
```

`movel` 과 같은 문(`program/plan`)이지만 **MOVE 노드를 여러 개** 한 프로그램에 싣고 `continues:true` 로 잇는다.
`movel` 은 노드 1개 = 구간 1개라 점 71개를 그리려면 70번 호출해야 하고 매 점에서 속도가 0을 찍는다 —
이 경로에는 쓸 수 없었다. 체인 구성은 [`hcr5_comm/README.md`](../hcr5_comm/README.md) §6.3 을 따른다.

- **입력** — 최상위 `"points": [[x,y,(z)], …]`, base 좌표계, 단위는 `"units"` 필드. **점의 z 는 안 쓴다** — `--z` 가 정한다
- **IK 는 `poseType:"tcp"` 로 푼다** — 그래서 `--z` 는 펜 끝 높이다. 08-17 실측: `--z -19` 의 IK→FK 왕복 오차 **0.0000mm**
- **L28 을 밟지 않는다** — tcp·flange 슬롯을 FK 두 번으로 각각 채우므로 컨트롤러가 어느 슬롯을 쓰든 같은 점이다
- **ros2_control 스택과 배타다** (`movel`·`movej` 와 같은 이유, README §1.2). rclcpp 의존이 없다

## 2. 08-17 실기에서 확정된 것

### 2.1 `150033` 의 원인 세 가지 — 셋 다 "특이점" 이 아니었다

컨트롤러는 셋 다 *"there might be singular points"* 라고 말한다. 갈라 보니 원인이 셋이었다.
상세 실측은 `stroke.cpp` 의 `kDefaultMinSegMm` · `kDefaultMaxSensitivityDegPerMm` · `kDefaultChain` 주석.

| 원인 | 증거 | 처치 |
|---|---|---|
| 웨이포인트 간격이 너무 좁다 | 최단 5.590mm 경로는 완주, 1.598mm 가 섞이면 거부 | 2mm 미만 세그를 버린다 |
| 체인이 룩어헤드를 넘는다 | 에러 `params` 가 노드 수·세그 길이와 무관하게 늘 `{"0":0,"1":8}` · 체인 3 ✅ / 8 ❌ / 9 ❌ | 6 마다 끊는다 (`radius:0` 이라 선은 안 끊긴다) |
| 야코비안 조건수 | 해는 있고 이웃 해와도 가까운데 직교 속도로 낼 수 없다 | 게이트 ④ |

### 2.2 그 밖의 실측

- **`program/plan` 적재 크기** — **73 노드 · 265.8KB** 를 받았다. `hcr5_comm/README.md` 의 *"plan 크기 한계 실측"* 항목은
  **적재 쪽으로는** 이 규모까지 문제없다 (실행 쪽 한계는 위 룩어헤드가 먼저 걸린다)

  · bbox **178.6×200.7mm** · 예상 **47초** · 민감도 최대 0.23 도/mm · MOVE 노드 71개(스트로크 68 · 접근이탈 3) · 263.6KB

## 3. 전 경로가 관절한계로 멈췄다

### 3.1 원인 — 팔꿈치가 −140° 근처까지 접힌다

로그 없이 정지만 보고됐다. 시스템에서 거꾸로 짚었다:

- 정지 후 상태는 깨끗했다 — `SERVO_OFF` · `IDLE` · 래치된 고장 없음 · **`limitCheck` 켜짐**.
  소프트 관절제한은 래치 안 되고 한계에서 얌전히 멈춘다(`hcr5_comm/README.md` §8 *"소프트 관절제한(limitCheck)은 래치 안 됨"*)
- `--z -19` dry-run 은 게이트를 전부 통과했다 → 계획 단계 거부가 아니라 **실행 중 컨트롤러 정지**다
- 웨이포인트와 **세그 내부 샘플** 모두에서 elbow 최심값이 **−139.783°**(`--z -19`). 부분 경로가 완주한 `--z 30` 에서는 **−136.573°**
- 공식 가동범위 J3 **±165°** 는 안 넘었다 (여유 25.2°)

> **가설** — 컨트롤러의 elbow 소프트 한계가 **약 ±140°** 다 (−139.783 이 −140 에서 0.217° 떨어져 있다).
> **실측하지 않았다.** 아래 손목반전 분기는 이 가설이 틀려도 81° 여유가 있어 가설에 기대지 않는다.

### 3.2 대안 — 손목반전 IK 분기

`robot/convertJointAngle` 은 **시드에 가장 가까운 해**를 준다. 같은 펜 자세에 해 브랜치가 여럿 있다.
**손목반전 시드** = joint_5 부호 반전 · joint_6 +180°. 이 분기에서 전 경로를 다시 풀었다:

| | 기존 분기 | 손목반전 분기 |
|---|---|---|
| elbow 범위 | 최심 −139.8° | **[−83.94°, −10.75°]** |
| 한계 여유 | 0.2° (가설 기준) | **81.06°** |
| IK 실패 | — | **0건** (세그 내부 포함 178 샘플, 브랜치 튐 없음) |
| 민감도 최대 | 0.23 도/mm | **1.43 도/mm** — 게이트 4.5 의 1/3 |

⚠️ 대가가 있다 — 먼 쪽에서 elbow 가 −10.75° 까지 **펴져** 신장 특이점에 가까워진다(민감도 6배).

**리빌드 없이 쓰는 법** — `stroke` 는 IK 시드를 **현재 로봇 자세**에서 가져온다. 그래서 로봇을 먼저 반전 자세로
옮겨 놓으면 기존 바이너리가 그 분기를 그대로 이어받는다. 08-17 에 넘긴 경유 절차:
`mqtt_cmd.py movej … --max-delta 30` **7단계**(각 29.76°). 각 단계 TCP 높이를 FK 로 확인했다 —
434 → 593 → 702 → 690 → 558 → 381 → **250mm**(최저, 종이면에서 269mm 위). 팔이 위로 크게 넘어간다
(최대 x≈679 · y≈−296 · z≈713) — 그 반경을 비우고 e-stop 을 잡을 것.

**게이트 ③ 오탐** — 반전 분기의 최장 세그(89.85mm)에서 관절 변화가 **29.704°** 라 기본 20° 에 걸린다.
민감도는 0.33 도/mm 로 정상적인 긴 구간 변화다 → `--max-jump 35` 로 푼다. 진짜 브랜치 튐(≈180°)은 35° 로도 잡힌다.

**고르지 않은 대안** — 종이를 +x 로 옮기면 elbow 가 약 0.175°/mm 씩 얕아진다(+40mm → −132.771°).
Mark 는 경유점으로 관절범위를 피하는 쪽을 골랐다.

# ros2_control 하드웨어 인터페이스 구성 — 중간결과물 (260809 산국)

**대상**: 플러그인 `hcr_bridge/HcrSystemInterface`(신설 예정 — 현행 선언은 `mock_components/GenericSystem`) ·
`markch/hcr5_ros2@83a5c4e` · 검증환경 09pc · 컨테이너 `moveit2_dev:jazzy`(ros2_control **4.45.2**) · **실기 없음**

> ⚠️ **채운 순서가 틀과 다르다** — 구현 전에 **기존 문서만으로** 계약을 먼저 고정했다(Mark 지시, 260809).
> 그래서 §3·§4 의 '구현/상태' 칸은 전부 **미착수**다. 수치는 실측 원본(hcr_comm README·hcr_bridge)에서 왔고,
> 이 세션이 새로 확인한 것은 컨테이너 안 ros2_control **4.45.2** 의 API 뿐이다.

## 결론 (≤2줄, 서술)
ros2_control **4.45.2**(Jazzy)가 하드웨어 컴포넌트별 `rw_rate`·`is_async` 를 지원하므로, 08-05 에 `SystemInterface` 를 기각한 세 근거 중 **주기 불일치(29.1Hz↔100Hz)는 구조적으로 해소된다**(사실 — 컨테이너에서 XML 속성·`HardwareInfo` 필드 확인).
그래서 **모드 2종을 다 구현한다**(계획) — ① 실기 없이 도는 **mock**(`use_mock:=true`, 명령 루프백) ② **실기를 실제로 움직이는 모드**(`HcrSystemInterface` + `allow_motion:=true`). 남은 두 기각 근거(자율주행 실행 모델 · 컨트롤러가 보간 소유)는 그대로여서 ②는 **점대점 한정**이고 연속 스트로크는 `program/plan` 에 남긴다(가설 — 실기 미검증).

## 1. 인터페이스 계약 (행 = 인터페이스 1종)
| 인터페이스 | 방향 | 대상 관절 | 단위 | 실기 원천·귀착 | 규약 변환 | 갱신 |
|---|---|---|---|---|---|---|
| position | command | `joint_1`~`joint_6` | rad | → `move/joint/here {jointAngle:[j1..j6]}` (도). `allow_motion=false` 면 **발행 없음** | `urdfRadToRealDeg` = `(deg−DELTA)/SIGN` — `joint_convention.hpp:53` | 변화 시에만 · 재발행 간격 **≥137ms** |
| position | state | 〃 | rad | ← `motion/joint/position` `{base…wrist3}` (도) | `realDegToUrdfRad` = `SIGN·deg+DELTA` — `joint_convention.hpp:43` | **29.1Hz** (버스 실측) |
| velocity | state | 〃 | rad/s | **원천 없음** — `motion/joint/speed` 는 내용 미규명 (hcr_comm README §3) | 변환 후 position 을 수신 간격으로 차분 | **29.1Hz** — 새 표본이 온 주기에만 |

행 근거 = `hcr_moveit_config/config/ros2_controllers.yaml:15-19`. 늘리려면 그 파일도 같이 고친다.
**`velocity` state 는 실기 원천이 없는 산출값이다**(사실). 안 채우면 JTC 가 0/NaN 을 피드백으로 쓰고, 부정확하면
허용오차 위반이 헛나온다 — 산출 품질이 안 나오면 이 행과 그 파일의 `state_interfaces` 를 **같이 줄이는 게 정직하다**.
`SIGN`/`DELTA` 는 아핀이라 변환 전후 어느 쪽에서 차분해도 같다(사실).

## 2. 주기·정합 (행 = 주기원 1건 — 이 로봇의 핵심 쟁점)
| 주기원 | 값 | 근거 | read()/write() 처리 |
|---|---|---|---|
| controller_manager update_rate | **100Hz** | 설정 (`ros2_controllers.yaml:4`) | 손대지 않는다 — 하드웨어 주기를 `rw_rate` 로 분리한다 |
| 실기 상태 버스 | **29.1Hz** (주기 **34.4ms**) | 실측 (hcr_comm README §5.2) | `<ros2_control … rw_rate="30">`. MQTT 콜백이 캐시에 쓰고 `read()` 는 **캐시 복사만** — 블로킹 없음 |
| 명령 RPC 왕복(ack) | **115~137ms** | 실측 (hcr_comm README §4) | `is_async="true"` 로 워커 스레드 분리. 동기 `pubWithAck` 를 `write()` 안에서 부르면 100Hz 루프가 **최대 13.7주기** 멈춘다 |
| 궤적 보간 소유자 | 점대점 = **JTC** / 연속 스트로크 = **로봇 컨트롤러** | 설계 | `write()` 는 점대점 목표만 낸다. 스트로크는 `program/plan` — **이 계약 밖**(hcr_bridge README §5) |

`rw_rate`·`is_async` 는 `<ros2_control>` 태그 **속성**이고 세부는 `<properties><async …/></properties>` 다 —
컨테이너의 `ros2_control_test_assets/descriptions.hpp:818-897` 에서 확인(사실).
`rw_rate` 가 `update_rate` 의 약수여야 하는지는 확인 못 했다(미검증 — 100/30 은 정수배가 아니다) → 검증 V-6.

## 3. 라이프사이클 (행 = 콜백 1개 — 행 목록 고정)
| 콜백 | 하는 일 | 실기 호출 | 실패 시 반환 | 구현 |
|---|---|---|---|---|
| `on_init` | `HardwareComponentInterfaceParams` 에서 `host`·`port`·`allow_motion`·`deadband_deg` 파싱. 관절 **6개**·인터페이스 집합(cmd position / state position·velocity)을 URDF 선언과 대조 | — | ERROR | 미착수 |
| `export_state_interfaces` | **재정의하지 않는다** — 4.45.2 에서 deprecated, 기반 클래스가 URDF 선언대로 자동 export | — | — | 해당 없음 |
| `export_command_interfaces` | 〃 (재정의가 필요해지면 `on_export_command_interfaces()` 쪽을 쓴다) | — | — | 해당 없음 |
| `on_configure` | MQTT 접속 · `motion/joint/position`·`status/operation`·`event/collision` 구독 · **첫 상태 표본 수신까지 대기(≤3s)** | 구독만 (무동작) | ERROR | 미착수 |
| `on_activate` | 필드버스 `FIELD_BUS_SW_STATE_CONNECTED` 확인 · 상태 신선도 확인 · **명령 버퍼를 현재 실기 자세로 초기화** (첫 `write()` 의 도약 방지) | `get/command/pos` (읽기) | ERROR | 미착수 |
| `read` | 캐시된 최신 관절값 → 규약 변환 → position state, 차분 → velocity state. **>1s 무수신이면 DEACTIVATE** (낡은 자세를 참으로 믿게 두지 않는다) | (구독 콜백) | ERROR/DEACTIVATE | 미착수 |
| `write` | `allow_motion=false` → 무동작. true → 게이트 5종(§5) 통과 시 `move/joint/here` 를 워커에 **큐잉**. 목표가 멎으면 데드밴드와 무관하게 **마지막 값 1회 발행**(전정밀도 유지, hcr_comm README §5.3) | `move/joint/here` | ERROR | 미착수 |
| `on_deactivate` | `move/stop` 발행 후 발행 잠금. 서보는 **끄지 않는다**(브레이크 체결 판단은 사람) | `move/stop` | SUCCESS (발행 실패해도 진행) | 미착수 |
| `on_error`·`on_cleanup` | `on_error`: `move/stop` + 발행 영구 잠금 · `on_cleanup`: MQTT 종료·워커 회수 | `move/stop` | SUCCESS | 미착수 |

## 4. 구성 파일 (행 = 파일 1건)
| 파일 | 역할 | 이번 변경 | 상태 |
|---|---|---|---|
| `*.ros2_control.xacro` | 플러그인·인터페이스 선언 | ① 플러그인 인자화(`use_mock`) — **xacro 3단 관통**(`hcr_robot.urdf.xacro`→`hcr_robot.xacro:7-8`→매크로) ② `rw_rate="30"` `is_async="true"` 추가 ③ `initial_value` 를 URDF 홈 `[1.570796,0,1.570796,0,1.570796,0]` 으로 교체 — **현행 `[0,0,1.5669,−1.59,−1.4695,0]` 은 폐기된 SRDF 값**(T16 ③, 실기 홈에서 715mm) | 미착수 |
| `ros2_controllers.yaml` | 컨트롤러·주기 | **변경 없음** — `update_rate:100`, cmd=position, state=position·velocity, `allow_nonzero_velocity_at_trajectory_end:true` 유지 | 현행 유지 |
| `<plugin>.xml` + CMakeLists | pluginlib 등록 | `hcr_bridge` **안에 플러그인 타깃 추가**가 기본안 — `mqtt_client`·`joint_convention` 을 배선 없이 재사용한다. 별도 패키지로 뺀다면 `hcr_bridge/CMakeLists.txt` 에 `ament_export_targets`·`ament_export_dependencies` **선행 필요**(현재 없어 하위 패키지가 링크 못 함) | 미착수 |
| `<hw_interface>.hpp/.cpp` | 구현 | 신설. 배치는 `ws_moveit2/src/` 아래여야 한다 — `compose.yml` 이 `ws_moveit2` 와 `hanwha_robot_arm` 만 마운트해 **`src/drivers/` 는 컨테이너에서 안 보인다**(이 디렉터리는 문서 전용) | 미착수 |
| launch | 기동·인자 | `demo.launch.py` 의 `MoveItConfigsBuilder.robot_description(..., mappings={"use_mock": …})` 로 인자 전달. **libmosquitto·nlohmann-json 은 이미지에 이미 있다**(`Dockerfile:75`) — 업무목록 T15 의 "Dockerfile 추가 필요"는 08-05 에 해소됨 | 미착수 |

**구성 모드는 이 셋이 전부다** — `use_mock` 은 *어떤 플러그인을 로드하는가*, `allow_motion` 은 *로드된 실기
플러그인이 실제로 발행하는가*로 서로 독립이다. mock 은 명령을 그대로 상태로 되돌리는 **루프백**이라 실기가 필요 없다.

| 모드 | 플러그인 (`use_mock`) | `allow_motion` | 상태 출처 | 로봇 |
|---|---|---|---|---|
| sim | `mock_components/GenericSystem` (**true**) | — | 명령 루프백 | 안 움직임 · **실기 불필요** |
| 실기 읽기 | `hcr_bridge/HcrSystemInterface` (false) | **false** | 실기 MQTT **29.1Hz** | 안 움직임 |
| 실기 쓰기 | 〃 | **true** | 〃 | **움직인다 — e-stop 대기 필수** |

## 5. 안전 게이트 (행 = 게이트 1건)
| 게이트 | 기본값 | 해제 조건 | 확인 방법 |
|---|---|---|---|
| 동작 지령 잠금 | `allow_motion` = **false** (hcr_bridge 와 같은 규약) | 파라미터 true + 실기 e-stop 대기 | `ros2 control list_hardware_components` · `write()` 발행 로그 부재 |
| 상태 무수신 타임아웃 | **1.0s** | 표본 재수신 | 버스 차단 → `read()` 가 DEACTIVATE, 컨트롤러 비활성 전이 |
| 필드버스 상태 감시 | `controllerStatus == FIELD_BUS_SW_STATE_CONNECTED` | 컨트롤러 복구(08-05 은 재부팅으로만) | `status/operation` 구독 로그 |
| 충돌 래치·해제 | `event/collision` 수신 시 발행 래치 | `event/collision/clear` 를 **사람이** 발행 | 로그 + `status/operation.collisionMitigation` |
| 데드맨 우회 고지 | — | — | 기동 시 경고 1회 — PC MQTT 명령은 펜던트 인에이블을 **안 거친다** |
| 관절한계 검사 | 공식 ±360°, **J3 ±165°** (Appendix F) | 없음 (상시) | `withinLimits()` — `joint_convention.hpp:70`. URDF 한계와 **둘 다** 본다 |
| 재발행 간격·데드밴드 | **≥137ms** · **0.01°** | 없음 (상시) | 발행 로그 간격. ⚠️ 이동 중 재발행이 선행 이동을 선점하는지 **미검증** — 첫 실기 실험은 정지 상태 단발로 |

**동시 접속 중재는 게이트로 두지 않는다 — 전제다**(Mark, 260809). 컨트롤러 랜선을 **PC 1대에만** 물리므로 실기
쓰기 주체가 구조적으로 하나다. 브로커는 무인증·무중재라 이건 소프트웨어가 아니라 **배선이 지키는 전제**이며,
허브를 끼우거나 실기 모드를 여러 PC에 배포하면 그 순간 깨진다(이미지를 공유해도 원격 PC 는 mock 만 쓸 수 있다).

## 남은 것 (≤3줄)
- **결정 완료 (Mark, 260809)** — 모드는 **sim(mock) + 실기 쓰기 둘 다** 구현한다. '실기 읽기'는 별도 모드가 아니라 실기 쓰기의 기본 상태(`allow_motion=false`)로 둔다.
- **이 문서는 계약이지 실측이 아니다** — 검증.md 는 **최종 검수**이므로 그 앞에 **구현·실측 세션이 반드시 들어간다**. 표값 **전부**가 검수 대상이고, 그중 근거가 아예 없이 설계로만 정한 3건은 `rw_rate`↔`update_rate` 정수배 요구(V-6) · `move/joint/here` 재발행 선점(V-7) · 차분 velocity 품질(V-5).
- 08-05 기각 결정의 **반전/병행 판정**은 이 문서가 근거만 대고, 판단은 최종결과물 '차이' 절에서 한다.

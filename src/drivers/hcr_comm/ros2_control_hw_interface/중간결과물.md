# ros2_control 하드웨어 인터페이스 구성 — 중간결과물 (260809 산국·매발톱·동백·수련)

**대상**: 플러그인 `hcr_bridge/HcrSystemInterface` **(신설 완료)** · `markch/hcr5_ros2` · 검증환경 09pc ·
컨테이너 `moveit2_dev:jazzy`(ros2_control **4.45.2**)

> **채운 순서와 주체** — ① 계약을 구현 전에 문서만으로 고정(**산국**, Mark 지시) → ② 병렬 3분할로 구현·실측:
> **매발톱**(S2, xacro·launch·mock 회귀) · **동백**(S3, 실기 읽기 전용 계측) · **수련**(S1, 플러그인 구현·병합).
> **원 계약 문장은 지우지 않았다** — 실측이 계약과 어긋나는 곳은 계약을 남긴 채 나란히 적었다.
>
> ⚠️ **실기 대면 구간(B·C)은 미착수다.** 플러그인은 실기 없이 도는 A 구간까지만 실측됐고, `on_activate`·
> `read`·`write` 는 **실기에서 한 번도 안 돌았다**. 실기 계측값은 전부 S3 의 **독립 구독**에서 왔다.

## 결론 (≤2줄, 서술)
ros2_control **4.45.2**(Jazzy)가 하드웨어 컴포넌트별 `rw_rate`·`is_async` 를 지원하므로, 08-05 에 `SystemInterface` 를 기각한 세 근거 중 **주기 불일치(29.1Hz↔100Hz)는 구조적으로 해소된다**(사실 — 컨테이너에서 XML 속성·`HardwareInfo` 필드 확인, S2 가 mock 으로 `rw_rate=30`·`is_async=true` 를 실제로 세워 재확인).
그래서 **모드 2종을 다 구현한다**(계획) — ① 실기 없이 도는 **mock**(명령 루프백, **회귀 7/7 통과**) ② **실기를 실제로 움직이는 모드**(`HcrSystemInterface` + `allow_motion:=true`, **구현 완료·실기 미검증**). 남은 두 기각 근거(자율주행 실행 모델 · 컨트롤러가 보간 소유)는 그대로여서 ②는 **점대점 한정**이고 연속 스트로크는 `program/plan` 에 남긴다(가설 — 실기 미검증).

## 1. 인터페이스 계약 (행 = 인터페이스 1종)
| 인터페이스 | 방향 | 대상 관절 | 단위 | 실기 원천·귀착 | 규약 변환 | 갱신 |
|---|---|---|---|---|---|---|
| position | command | `joint_1`~`joint_6` | rad | → `move/joint/here {jointAngle:[j1..j6]}` (도). `allow_motion=false` 면 **발행 없음** | `urdfRadToRealDeg` = `(deg−DELTA)/SIGN` — `joint_convention.hpp:53` | 변화 시에만 · 재발행 간격 **≥137ms** |
| position | state | 〃 | rad | ← `motion/joint/position` `{base…wrist3}` (도) | `realDegToUrdfRad` = `SIGN·deg+DELTA` — `joint_convention.hpp:43` | **29.1Hz** (버스 실측) → **29.21·29.26Hz 재확인** (S3, 35s×2회) |
| velocity | state | 〃 | rad/s | 계약: **원천 없음** — `motion/joint/speed` 는 내용 미규명 (hcr_comm README §3)<br>⚠️ **실측: 그 토픽은 발행된다**(S3) — 아래 | 변환 후 position 을 수신 간격으로 차분 | **29.1Hz** — 새 표본이 온 주기에만 |

행 근거 = `hcr_moveit_config/config/ros2_controllers.yaml:15-19`. 늘리려면 그 파일도 같이 고친다.
`SIGN`/`DELTA` 는 아핀이라 변환 전후 어느 쪽에서 차분해도 같다(사실).

**⚠️ 계약 전제가 사실과 달랐다 — `motion/joint/speed`** (S3 실측, 보고 의무 항목).
발행된다. **9.82Hz**(평균 101.88ms, SD 4.30ms) 로 position 의 **≈1/3 주기**이고, 관절 키 6개·봉투가 position 과 **동일**하다.
정지 상태 값이 35초 내내 고정이고 base 만 정확히 `0`, 나머지는 인코더 1~3.5카운트 상당의 **양수** — **단위·부호 미상**(업무목록 **T19**).
→ **판정: 계약대로 차분을 유지한다**(Mark·S1). 근거 둘 — ① 차분 품질이 이미 확인됐다(정지 구간 **정확히 0.0000 rad/s**, 1024표본, 관절값 SD **0.000000°**) ② speed 를 채택하면 velocity state 갱신이 **1/3 로 느려진다**. 단위·부호가 밝혀지면 재검토한다.

**`velocity` state 는 실기 원천이 없는 산출값이다**(사실). 안 채우면 JTC 가 0/NaN 을 피드백으로 쓰고, 부정확하면
허용오차 위반이 헛나온다 — 산출 품질이 안 나오면 이 행과 그 파일의 `state_interfaces` 를 **같이 줄이는 게 정직하다**.

## 2. 주기·정합 (행 = 주기원 1건 — 이 로봇의 핵심 쟁점)
| 주기원 | 값 | 근거 | read()/write() 처리 |
|---|---|---|---|
| controller_manager update_rate | **100Hz** | 설정 (`ros2_controllers.yaml:4`) | 손대지 않는다 — 하드웨어 주기를 `rw_rate` 로 분리한다 |
| 실기 상태 버스 | **29.1Hz** (주기 **34.4ms**) → **29.21·29.26Hz** (S3 재측정, 최대 간격 **75.33ms**) | 실측 (hcr_comm README §5.2 · S3 35s×2회) | `<ros2_control … rw_rate="30">`. MQTT 콜백이 캐시에 쓰고 `read()` 는 **캐시 복사만** — 블로킹 없음 |
| 명령 RPC 왕복(ack) | **115~137ms** | 실측 (hcr_comm README §4) | `is_async="true"` **+ 플러그인 자체 워커 스레드**. 동기 `pubWithAck` 를 `write()` 안에서 부르면 100Hz 루프가 **최대 13.7주기** 멈춘다 |
| 궤적 보간 소유자 | 점대점 = **JTC** / 연속 스트로크 = **로봇 컨트롤러** | 설계 | `write()` 는 점대점 목표만 낸다. 스트로크는 `program/plan` — **이 계약 밖**(hcr_bridge README §5) |

`rw_rate`·`is_async` 는 `<ros2_control>` 태그 **속성**이고 세부는 `<properties><async …/></properties>` 다 —
컨테이너의 `ros2_control_test_assets/descriptions.hpp:818-897` 에서 확인(사실).

**주기 관련 실측 3건 (전부 사실)**
- **`rw_rate="30"` 정당** — 실측 29.2Hz 는 30Hz 와 **2.6% 차**(S3).
- **`read()` 무수신 타임아웃 1.0s 는 헛발동하지 않는다** — 최대 수신 간격 **75.33ms** 대비 **13.3배** 여유. 단 **100ms 이하로 조이면 헛발동한다**(S3).
- **CM 은 100/30 비정수배를 거부하지 않는다** — S2 가 mock 으로 세워 확인. `list_hardware_components` 가 `read/write rate: 30 Hz`·`is_async: True` 를 직접 찍고, `is_async` 는 *"Starting async handler…"* 로그로 **속성값이 실제로 읽힌 것**이 확인된다.
- **V-6 은 절반만 닫혔다** — *구조적 거부가 없다*는 확인됐고(사실), *실기에서 그 불일치가 기능적으로 문제되는가*(낡은 표본을 JTC 가 어떻게 받는가)는 **여전히 미검증**(B3).

**`is_async`·`rw_rate` 파서 함정 2건** (S2, 사실) — `parse_bool` 은 **대소문자 무관**이라 xacro 가 내는 `"True"`/`"False"` 를 그대로 받지만 **`1`·`0`·빈 문자열은 예외를 던진다**. `rw_rate` 는 **양의 정수만** 받는다 — 기본값을 `0` 으로 두면 안 뜬다.

## 3. 라이프사이클 (행 = 콜백 1개 — 행 목록 고정)
| 콜백 | 하는 일 | 실기 호출 | 실패 시 반환 | 구현 |
|---|---|---|---|---|
| `on_init` | `HardwareComponentInterfaceParams` 에서 `host`·`port`·`allow_motion`·`deadband_deg` 파싱. 관절 **6개**·인터페이스 집합(cmd position / state position·velocity)을 URDF 선언과 대조 | — | ERROR | **완료 · A3 실측** — 이름·**순서**까지 대조한다 |
| `export_state_interfaces` | **재정의하지 않는다** — 4.45.2 에서 deprecated, 기반 클래스가 URDF 선언대로 자동 export | — | — | **해당 없음 — 자동 export 확인**(6/6/6, S2 DoD 3) |
| `export_command_interfaces` | 〃 (재정의가 필요해지면 `on_export_command_interfaces()` 쪽을 쓴다) | — | — | 해당 없음 |
| `on_configure` | MQTT 접속 · `motion/joint/position`·`status/operation`·`event/collision` 구독 · **첫 상태 표본 수신까지 대기(≤3s)** | 구독만 (무동작) | ERROR | **완료 · A3 실측 3경로** — 아래 |
| `on_activate` | 필드버스 `FIELD_BUS_SW_STATE_CONNECTED` 확인 · 상태 신선도 확인 · **명령 버퍼를 현재 실기 자세로 초기화** (첫 `write()` 의 도약 방지) | `get/command/pos` (읽기) | ERROR | **완료 · 실기 미검증**(B1) |
| `read` | 캐시된 최신 관절값 → 규약 변환 → position state, 차분 → velocity state. **>1s 무수신이면 DEACTIVATE** (낡은 자세를 참으로 믿게 두지 않는다) | (구독 콜백) | ERROR/DEACTIVATE | **완료 · 실기 미검증**(B2·B3·B4·B5) |
| `write` | `allow_motion=false` → 무동작. true → 게이트 5종(§5) 통과 시 `move/joint/here` 를 워커에 **큐잉**. 목표가 멎으면 데드밴드와 무관하게 **마지막 값 1회 발행**(전정밀도 유지, hcr_comm README §5.3) | `move/joint/here` | ERROR | **완료 · 실기 미검증**(C1~C4) |
| `on_deactivate` | `move/stop` 발행 후 발행 잠금. 서보는 **끄지 않는다**(브레이크 체결 판단은 사람) | `move/stop` | SUCCESS (발행 실패해도 진행) | **완료 · 실기 미검증** |
| `on_error`·`on_cleanup` | `on_error`: `move/stop` + 발행 영구 잠금 · `on_cleanup`: MQTT 종료·워커 회수 | `move/stop` | SUCCESS | **완료 · 실기 미검증** |

**A3 — 로봇 없이 플러그인 로드 (실측 3경로, 전부 사실).** 플러그인이 **발견·로드되고** `on_configure` 가 **사유별로 다른 메시지를 내며 상한 안에 죽는다**.

| 경로 | 조건 | 소요 | 메시지 |
|---|---|---|---|
| ① 무응답 호스트 | `192.168.0.99:1883` | **3.004s** | "브로커에 TCP 로 닿지 않는다" |
| ② 접속 거부 | `127.0.0.1:18830` (아무도 안 듣는다) | 즉시 | 〃 |
| ③ 브로커만 붙음 | 최소 MQTT 스텁 브로커 | **3.011s** | "첫 표본을 3000ms 안에 못 받았다 — 브로커는 붙었지만 로봇이 상태를 안 낸다" |

①이 **3초에 끊기는 것이 설계 요점**이다 — `mosquitto_connect` 는 블로킹이고 취소가 안 돼 무응답 호스트에서 OS 기본 타임아웃(수십 초~2분)에 잡힌다. 그래서 그 앞에 **시간 상한을 건 TCP 프로브**를 둔다(`hcr_system_interface.cpp` `tcpProbe`).

⚠️ **그 뒤 controller_manager 가 프로세스째 abort 한다**(사실) — `Failed to set the initial state of the component … to active` → `std::runtime_error` → SIGABRT + 스택트레이스. **플러그인은 계약대로 ERROR 를 반환했고 abort 는 프레임워크 거동이다.** 실기 없이 실기 모드를 띄우면 데모가 통째로 죽는다는 뜻이라, 기동 절차에 영향이 있다. 완화 후보 파라미터 `hardware_components_initial_state.{unconfigured,shutdown_on_initial_state_failure}` 가 `libcontroller_manager.so` 에 존재하는 것은 확인했으나 **효력은 미검증** — 시험이 낡은 `robot_state_publisher`(전송지속 QoS)에 오염돼 판정 못 했다.

**⚠️ 계약 §4 의 인자 이름을 바꿨다** — 계약은 `use_mock` **불리언**이었으나 **플러그인 문자열 인자**로 뒤집었다(승인: Mark, 260809).
채택 이름 = 매크로 param `plugin` · 최상위 xacro:arg **`hardware_plugin`**. 이유는 동료 ysh 의 `hcr5_description` 과 **글자까지 같게** 두어 이식을 한 줄로 만들기 위해서다.
**실기 전환은 인자 하나다** — `hardware_plugin:=hcr_bridge/HcrSystemInterface rw_rate:=30 is_async:=true`.

**구성 모드는 이 셋이 전부다** — `hardware_plugin` 은 *어떤 플러그인을 로드하는가*, `allow_motion` 은 *로드된 실기
플러그인이 실제로 발행하는가*로 서로 독립이다. mock 은 명령을 그대로 상태로 되돌리는 **루프백**이라 실기가 필요 없다.

**설계 메모 2건**
- **데드밴드와 최종값의 관계** — 데드밴드는 *목표가 움직이는 동안*만 건다. 목표가 멎으면(직전 주기와 같으면) 데드밴드와 무관하게 **최종값을 전정밀도로 1회** 낸다. 안 그러면 궤적 끝에서 데드밴드만큼 못 미친 자리에 선다.
- **ack 없으면 보냈다고 치지 않는다** — 워커는 `pubWithAck` 응답이 있을 때만 `last_sent` 를 갱신한다. 그래야 다음 목표가 데드밴드에 먹히지 않는다.

**동시 접속 중재는 게이트로 두지 않는다 — 전제다**(Mark, 260809). 컨트롤러 랜선을 **PC 1대에만** 물리므로 실기
쓰기 주체가 구조적으로 하나다. 브로커는 무인증·무중재라 이건 소프트웨어가 아니라 **배선이 지키는 전제**이며,
허브를 끼우거나 실기 모드를 여러 PC에 배포하면 그 순간 깨진다(이미지를 공유해도 원격 PC 는 mock 만 쓸 수 있다).

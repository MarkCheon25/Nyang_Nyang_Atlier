**행 규칙**
- 복수 확인 **병합 금지** — 병합되면 1건의 실패가 통과에 동봉된다
- **행 삭제 금지** — 실행 못 한 행은 실측 칸에 사유 한 단어(실기 필요/접근 불가/소진) + 판정 '미검증'
- 실행 후 추가한 행은 ID 에 `+` 표시
- 기각 조건이 도출 안 되는 기준("0건 이상")은 **등록 무효**
- 판정은 3값, 실측이 기준 밖이면 **자동 실패** (재량 통과 금지)

**행 유래** — V-1~V-9 는 틀의 원 9행(항목명 유지). V-10~V-15 는 중간결과물의 표값 중 원 9행이 안 덮는 것을

## 차이·특이 (≤3줄)
- **기준을 실측보다 먼저 등록했다**(260809 거베라, Mark 승인) — 구현자(수련)와 다른 세션이고 B·C 실기 대면 **전**이다. 실측 세션은 이 기준을 받아 쓴다.
- **V-6 의 방법이 틀에서 바뀌었다** — 틀은 `ros2 topic hz /joint_states` 였으나 그 토픽은 `rw_rate` 를 안 비춘다(S2 실측). 값 갱신 빈도로 교체했다.
- `motion/joint/speed` 단위·부호(T19)는 **검증 항목이 아니다** — 계약(position 차분 유지)의 **재검토 트리거**이고, 계약 자체의 검증은 V-13 이 한다.
- ⚠️ **V-11 의 기준 문구 "경로마다 다른 메시지"가 원본과 어긋난다** (260811-진공펌프 발견). 이 행의 유래인
  중간결과물 §3 A3 표는 **①과 ②를 같은 메시지(`〃`)로 이미 기록**하고 있다 — 코드가 두 경로를 같은
  `tcpProbe` 실패로 묶기 때문이다(설계대로). 즉 사전등록 때 원본을 옮기며 문구가 강해졌다(가설).
  실측은 그 A3 표와 **3/3 일치**한다. **기준을 조용히 고치지 않고 '미검증'으로 두었다** — 문구를
  *"실패 사유마다 다른 메시지(TCP 미도달 / 표본 미수신)"* 로 정정할지의 판정은 Rokey6.

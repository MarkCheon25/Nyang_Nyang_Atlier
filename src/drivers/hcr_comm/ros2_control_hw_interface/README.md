# ros2_control 하드웨어 인터페이스 — 작업 문서

세션 여러 개로 나눠 진행한다. 아래 3종이 각 세션의 **입력과 출력을 고정**한다.
틀은 260809-데이지 작성. **진척은 [`../README.md`](../README.md) §12 가 든다** — 세 문서를 하나씩 열지 않고
지금 어디까지 왔는지 보려면 거기를 본다.

## 세션 흐름

| 순서 | 세션 | 먼저 읽는 것 | 채우는 것 |
|---|---|---|---|
| ① | **구현·배선** (1~2개) | 최종결과물 | **중간결과물** |
| ② | **검증 = 최종 검수** (구현자와 **다른** 세션) | 최종결과물 · 중간결과물 | **검증** |
| ③ | **마무리** (1개) | 위 셋 전부 | **최종결과물** |

**모든 세션이 착수 전에 [최종결과물.md](최종결과물.md)를 확인한다** — 어디로 수렴하는지 알고 시작하기 위해서다.
검증을 구현자와 분리하는 이유: 만든 사람이 자기 작업을 판정하면 기준이 결과에 맞춰진다.

⚠️ **검증은 중간검수가 아니라 최종 검수다**(Mark, 260809) — 중간결과물 표값의 **일부가 아니라 전부**를 실제로
확인한다. 따라서 ①과 ② 사이에 **구현·실측이 완료돼 있어야** 한다. 계약만 있고 구현이 없으면 검증표가 전 행
'미검증'으로 끝난다. **260809 시점이 정확히 그 상태다** — 중간결과물은 구현 전에 문서만으로 채웠다.

```

    ▼
검증 (기준↔실측 대조) ──집계 통과 n/실패 n/미검증 n──┐
    │                                              │
    │ 포인터                                        │ M/N
    ▼                                              ▼
최종결과물 (결론·경위·계약 요약·산출물·차이·남은 것)
```

## 공통 규칙

- 제목 `# <작업 한 줄> — <문서> (YYMMDD 세션명)`
- **결론 선행** · 문장마다 `(사실)`/`(가설)` · 수치는 굵게
- 경로·근거는 **포인터**(`문서:절`·`file:line`) — 원본 재기술 금지, 인용 ≤3줄
- 해당 없는 절은 지우지 않고 **"없음"**
- 판정은 **Mark** — 에이전트 대필 금지

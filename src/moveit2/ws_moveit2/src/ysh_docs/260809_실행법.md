## 1. RViz 설정 — 손댈 것이 없다

`moveit.rviz` 에 두 디스플레이가 **이미 등록돼 있다** (2026-08-09 추가).
`demo.launch.py` 로 띄우면 처음부터 올라와 있고, 토픽이 아직 없어도 기다린다.

| 디스플레이 이름 | 토픽 | 색 | 뜻 |
|---|---|---|---|
| `펜 자취 (실제)` | `/pen_trail/trail` | 🔴 빨강 | **실제** 펜 끝이 지나간 자취 |
| `입력 도형 (계획)` | `/hcr5_examples/target_shape` | 🟢 초록 | **입력** 도형 (비전이 준 좌표) |

**둘을 겹쳐 보는 것이 이 테스트의 핵심이다.** 초록 위에 빨강이 정확히 얹히면 성공.
`/pen_trail/trail` 의 노란 구슬은 **현재** 펜 끝 위치다.

<details><summary>직접 띄운 RViz 라 디스플레이가 없다면</summary>

`Add` → `By topic` → 위 두 토픽 → `MarkerArray`

`/hcr5_examples/target_shape` 는 **Durability Policy 를 `Transient Local` 로 바꿔야 한다.**
발행자가 그리기 직전에 딱 한 번 쏘기 때문에, 기본값 `Volatile` 로 두면 이미 지나간
메시지를 받지 못해 초록 선이 안 보인다.

</details>

> **RViz 를 늦게 띄우면?** 예제 노드가 살아 있는 동안(약 35초)이면 `Transient Local`
> 구독이 마지막 메시지를 받아온다. 노드가 끝난 뒤에 붙으면 못 받는다 — 다시 실행할 것.
> 이미 받은 RViz 는 계속 보인다 (Marker `lifetime` 기본값 0 = 영구).

## 3. 인자 — 재빌드 없이 실험

```bash
ros2 launch hcr5_examples example.launch.py example:=draw_contour draw_size:=0.25
```

| 인자 | 기본 | 뜻 |
|---|---|---|
| `draw_size` | `0.15` | 도형의 **긴 변** 길이 [m] |
| `eef_step` | `0.002` | 데카르트 보간 간격 [m] — **작을수록 선이 매끄럽다** |
| `hover` | `0.03` | 펜을 들고 이동할 높이 [m] |
| `vel_scale` | `0.1` | 속도 스케일 (0~1) |
| `acc_scale` | `0.1` | 가속도 스케일 (0~1) |
| `execute` | `true` | `false` = 계획만. **도달 가능성만 빠르게 볼 때** |
| `go_home` | `true` | `false` = 현재 자세에서 바로 그림 |

> ⚠️ **`--ros-args -p draw_size:=0.25` 는 동작하지 않는다.**
> `ros2 launch` 는 그것을 노드로 전달하지 않는다. 위처럼 `key:=value` 로 줄 것.

**자주 쓰는 조합**

```bash
# 크기만 바꿔 도달 가능한지 빠르게 확인 (로봇을 움직이지 않는다)
ros2 launch hcr5_examples example.launch.py example:=draw_contour \
  execute:=false draw_size:=0.30

# 선을 더 매끄럽게 (평면 이탈이 줄어든다. 대신 느려진다)
ros2 launch hcr5_examples example.launch.py example:=draw_contour eef_step:=0.0005

# 빠르게 (모양 확인용)
ros2 launch hcr5_examples example.launch.py example:=draw_contour \
  vel_scale:=0.3 acc_scale:=0.3
```

## 5. 검증 — 자취를 수치로 확인

그리기가 끝난 뒤(자취가 남아 있는 상태에서) 자취 데이터를 받는다.

```bash
ros2 topic echo /pen_trail/trail --once --full-length > /tmp/trail.yaml
```

> ⚠️ **`--full-length` 가 필수다.** 없으면 `points` 배열이 `'...'` 로 잘려 파싱이 깨진다.
> 그리고 출력이 여러 YAML 문서라 파이썬에서는 `yaml.safe_load_all` 을 써야 한다.

간단 확인:

```bash
python3 - <<'EOF'
import yaml
pts=[]
for d in yaml.safe_load_all(open('/tmp/trail.yaml')):
    if not isinstance(d, dict): continue
    for m in d.get('markers', []):
        if isinstance(m, dict) and m.get('ns')=='pen_trail' and m.get('points'):
            pts=[(p['x'],p['y'],p['z']) for p in m['points'] if isinstance(p,dict)]
xs=[p[0] for p in pts]; ys=[p[1] for p in pts]; zs=[p[2] for p in pts]
print(f"{len(pts)} 점")
print(f"x 폭 {(max(xs)-min(xs))*1000:.1f} mm · y 폭 {(max(ys)-min(ys))*1000:.1f} mm")
print(f"z 폭 {(max(zs)-min(zs))*1000:.3f} mm  ← 평면 이탈 (하강·상승 구간 포함)")
EOF
```

**기준값 (`draw_size=0.15`, 2026-08-09 실측)**

| 항목 | 값 |
|---|---|
| 자취 bbox | 150.0 × 133.0 mm (입력 150.0 × 133.2) |
| 입력 대비 편차 평균 / 최대 | 0.064 / 0.404 mm |
| 평면 이탈 (펜 다운 구간) | 0.261 mm |

## 7. 문제 해결

### 7.1 ★ 먼저 이것부터 — 중복 실행 확인

```bash
pgrep -x move_group | wc -l      # 1 이어야 한다
pgrep -f ros2_control_node | wc -l
```

**2 이상이면 그것이 원인이다.** `move_group` 이 여럿이면 액션 goal 이 엉뚱한 인스턴스로
가고 TF 도 서로 다른 모델에서 나온다. 증상:

```
[ERROR] unknown goal response, ignoring...
[INFO]  Execute request aborted
[ERROR] MoveGroupInterface::execute() failed or timeout reached
```

정리:

```bash
# ⚠️ pkill -f 는 자기 자신을 먼저 죽인다. PID 로 직접 죽일 것.
ps -eo pid,args | grep -E "[m]ove_group|[r]os2_control_node|[r]obot_state_publisher|[s]tatic_transform|[p]en_trail|[r]viz2"
kill -9 <PID> <PID> ...
```

> `ps | grep -c` 는 **자기 명령줄까지 세어 오진**한다. 개수는 `pgrep` 으로 셀 것.

### 7.2 URDF 를 고친 뒤에는 반드시 다시 띄운다

`robot_state_publisher` 와 `move_group` 은 **기동 시점에** 모델을 읽고 그 뒤로 바꾸지
않는다. 띄워 둔 채로 URDF 를 고치면 **옛 모델로 계속 돈다** — 그리고 에러가 안 난다.

### 7.3 증상별

| 증상 | 원인 | 해결 |
|---|---|---|
| `executable 'draw_contour' not found` | 빌드 안 됨 / source 안 함 | `colcon build --packages-select hcr5_examples` 후 `source install/setup.bash` |
| 홈 자세 좌표가 (0.490, −0.1705, 0.2915) 가 아님 | 중복 실행 또는 옛 URDF | §7.1 · §7.2 |
| 달성률 < 100% | IK 끊김 / 작업영역 밖 | `draw_size` 를 줄이거나 `go_home:=true` 확인. 끊긴 웨이포인트 번호가 로그에 나온다 |
| `No acceleration limit was defined` | `joint_limits.yaml` 손보정 유실 | §6 스크립트 실행 |
| `Action client not connected` | `ros2_controllers.yaml` 인터페이스 빈 리스트 | §6 스크립트 실행 |
| RViz 에 빨간 선이 안 보임 | `pen_trail` 노드 미기동 | 터미널 2 실행 |
| RViz 에 초록 선이 안 보임 | Display 의 Durability 가 `Volatile` / 노드 종료 후 늦게 붙음 | §1 |
| Display 자체가 목록에 없음 | `moveit.rviz` 손보정 유실 (Setup Assistant 재생성) | §6 스크립트 `[H]` |
| 자취에 도형에 없는 직선이 하나 더 | `/pen_trail/clear` 실패 (터미널 2 가 안 떠 있었음) | 터미널 2 먼저 띄우고 재실행 |
| 세부(수염)가 뭉개짐 | `min_point_distance` 기본 2mm | `-p min_point_distance:=0.0002` |
| 손목에 43mm 틈 | **버그 아님** — 실기 손목이 CAD 보다 길다 | 무시. `260809_상세.md` §1.4 |
| `XML parsing error` (xacro) | XML 주석 안에 `--` 를 씀 | 다른 문자로 교체 |

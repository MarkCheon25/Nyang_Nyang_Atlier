## 1. 기구학 정본 교정 — 43mm

물려받은 CAD 치수가 실기와 달랐다. 인천이 08-05 에 컨트롤러 FK RPC 로 108 샘플 스윕해
교정한 값을 이식했다 — **109개 자세 RMS 43.4mm → 0.006mm.**

지배적 오류 하나: **`joint_6.x` −42.90mm.** J5 축에서 flange 까지가 실기는 132.5mm 인데
URDF 는 89.6mm 였다.

**이것이 위험한 이유는 에러가 안 나기 때문이다.** 달성률 100%, TOTG 성공, 실행 SUCCESS —
전부 정상으로 보이고 펜만 43mm 옆에 그린다. A4 폭이 210mm 다.

**관절 한계도 틀려 있었다.** 특히 `joint_5` 를 ±120° 로 두고 있었는데, **실기 wrist2 가
−267° 로 관측된다** — 이 상태로는 실기의 현재 자세조차 URDF 로 표현할 수 없어
상태 브릿지를 붙이는 순간 깨진다. ±360° 로 넓혔다 (joint_2·4 도 함께).

직접 재검증했다: 홈 자세 FK flange **(490.00, −170.50, 441.50) mm ≡ 펜던트 실측, 차이 0.01mm.**

**덤** — `pen_tip` TF 자세가 RPY (180°,0,0) 으로 나와 펜던트의 flange `rx=−180°` 와
일치했다. 기하 추론만으로 잡았던 `tool0` 이 **실기 flange 규약과 같다**는 뜻이고,
3단계에서 데카르트 자세를 넘길 때 미지의 회전 보정이 끼지 않는다.

**재발 방지** — 가드 스크립트에 [F]·[G] 신설. [F] 는 값 대조에 그치지 않고
**순기구학을 직접 풀어** 실측 좌표와 대조한다.

> ⚠️ RViz 에서 손목(`link5_1↔link6_1`)에 **43mm 틈**이 보인다. mesh origin 도 함께
> 재계산한 결과이고, **실기 손목이 CAD 보다 그만큼 길다**는 뜻이다. 기구학은 옳다.

## 2. `05_draw_contour` — 비전 좌표를 그대로 그린다

지금까지 예제는 우리가 만든 도형(사각형)이었다. 05 는 **비전이 이미지에서 뽑은 윤곽선**
(고양이 70점)을 받아 그린다. 실제 작업과 같은 형태다.

```
① SRDF home 으로 이동          펜이 −Z 를 향하는 자세
② 픽셀 → 로봇 좌표             x = cx − (v−v_c)·s ,  y = cy − (u−u_c)·s
③ 입력 도형을 초록 선으로 발행  /hcr5_examples/target_shape
④ 펜 든 채 시작점 위로          (이 선이 자취에 남지 않게 분리)
⑤ /pen_trail/clear             자취에 "그린 것만" 남기려고
⑥ 하강 → 윤곽선 → 상승         한 번의 데카르트 경로
```

**② 의 u·v 양쪽에 음부호가 붙는 것이 핵심이다.** 한쪽만 뒤집으면 거울상이 된다
(이미지 v 가 아래로 증가하는 보정 하나, 관찰자 오른쪽이 −Y 인 보정 하나).

**③ 이 2단계에 남겨 뒀던 "입력 도형 겹치기" 를 채운다.** `moveit.rviz` 에 디스플레이를
미리 등록해 뒀으니 **RViz 에서 손으로 Add 할 필요가 없다.** 초록(입력)과 빨강(자취)을
겹쳐 보면 편차가 눈에 보인다 — 선 품질의 1차 계측 수단.

좌표는 `kContour` 에 박아 뒀다. **vision 이 넘겨주면 거기만 갈아끼우면 된다.**

## 3. 알아 둘 것 — 편차의 정체

**mock 은 명령을 그대로 따른다. 그런데도 0.26mm 평면 이탈이 나온다.**
이 오차는 로봇이 아니라 **우리 파이프라인**에서 나온다.

```
computeCartesianPath 가 2mm 간격으로 IK 를 푼다
   → 그 사이는 컨트롤러가 관절 공간에서 선형 보간
   → 관절 공간 직선은 데카르트 공간에서 직선이 아니다 → 살짝 부푼다
```

**`eef_step` 을 줄이면 줄어든다.** 로봇 반복정밀도가 ±0.1mm 이므로, 파이프라인 오차가
그보다 크면 로봇을 탓해도 소용이 없다. **실기 선 품질 예산은 여기서부터 잡아야 한다.**

TOTG 가 궤적점을 병합하는 것도 해상도 바닥으로 작용한다 (2mm 보간 380 샘플 → 195 구간).

## 4. 막혔던 곳

| 증상 | 원인 | 해결 |
|---|---|---|
| `execute` 가 계속 abort · 홈 좌표가 이상 | **`demo.launch.py` 3중 실행** (하나는 URDF 교정 전에 뜬 것) | 전부 종료 후 하나만. `pgrep -x move_group \| wc -l` 로 확인 |
| `XML parsing error ... line 8` | XML 주석 안의 `------` — **주석에 `--` 금지** | `‾‾‾‾` 로 교체 |
| launch 파라미터가 안 먹음 | `ros2 launch` 는 `--ros-args -p` 를 **노드로 전달하지 않는다** | launch 인자로 선언 + `ParameterValue(..., value_type=)` |
| 자취 파싱 실패 | `ros2 topic echo` 가 긴 배열을 자름 | `--full-length` (+ `yaml.safe_load_all`) |
| 세부(수염)가 사라짐 | `pen_trail` 기본 필터 2mm > 최단 변 1.2mm | `-p min_point_distance:=0.0002` |

> **URDF 를 고쳤으면 떠 있던 세션을 반드시 다시 띄워야 한다.**
> `robot_state_publisher`·`move_group` 은 기동 시점에 모델을 읽고 그 뒤로 바꾸지 않는다.

## 2. 창 하나로 끝내는 절차

### ① 스택 기동 — 백그라운드, 창을 닫아도 안 죽는다

```bash
docker exec -d moveit2_dev bash -lc "source /opt/ros/jazzy/setup.bash && source ~/ws_moveit2/install/setup.bash && ros2 launch hcr_moveit_config demo.launch.py hardware_plugin:=hcr_bridge/HcrSystemInterface rw_rate:=30 is_async:=true allow_motion:=true > /tmp/launch.log 2>&1"
```

**실기 전환은 인자다** — `hardware_plugin`·`rw_rate`·`is_async`. 로봇을 실제로 움직이려면 `allow_motion:=true` 를 **더한다**
(기본값 `false` 라 잊으면 안 움직인다). 인자를 아예 빼면 mock 이라 실기가 필요 없다.

| 모드 | 인자 | 로봇 |
|---|---|---|
| sim (mock) | 없음 | 안 움직임 · **실기 불필요** |
| 실기 읽기 | `hardware_plugin:=… rw_rate:=30 is_async:=true` | 안 움직임 |
| 실기 쓰기 | 〃 + `allow_motion:=true` | **움직인다 — e-stop 대기 필수** |

### ② 준비 확인 — 15초쯤 뒤

```bash
docker exec moveit2_dev grep -E "Configured and activated|활성화 —|ERROR" /tmp/launch.log
```

컨트롤러 **2개**(`hcr_arm_controller`·`joint_state_broadcaster`)가 `Configured and activated` 로 나오면 준비 완료.
`활성화 — 명령 버퍼 = 실기 [...]°` 줄이 플러그인이 실기를 잡았다는 뜻이다.

### ③ 서보 ON

```bash
docker exec moveit2_dev bash -lc "cd ~/ws_moveit2 && python3 src/drivers/hcr_comm/tools/mqtt_cmd.py servo on"
```

### ④~⑥ 이동

목표는 **URDF rad** 로 준다. 실기 도(度)와의 대응은 규약 변환(README §1)을 거친 값이다.

| 점 | joint_1 | joint_2 | joint_3 | joint_4 | joint_5 | joint_6 | 실기 (도) | 비고 |
|---|---|---|---|---|---|---|---|---|
| **홈** | 1.570796 | 0 | 1.570796 | 0 | 1.570796 | 0 | `[0, −90, −90, −90, 90, 0]` | SRDF `hcr_home` |
| **P1** | **1.745329** | 0 | 1.570796 | 0 | 1.570796 | 0 | `[10, −90, −90, −90, 90, 0]` | base +10° |
| **P2** | **1.919862** | 0 | 1.570796 | 0 | 1.570796 | **0.349066** | `[20, −90, −90, −90, 90, 20]` | base +20° · wrist3 +20° |

**P1·P2 를 이 두 축으로만 잡은 이유** — 홈 자세에서 플랜지 높이가 **수학적으로 불변인 축은 joint_1(수직축 회전)과
joint_6(지금 아래를 향한 툴축 회전) 둘뿐**이다. 나머지 축(2·3·4·5)은 플랜지를 내릴 수 있어 작업대 클리어런스를
사람이 따로 확인해야 한다. 첫 수동 운전은 이 둘로만 한다.

```bash
# ④ 홈 → P1  (base +10°, 5초)
docker exec moveit2_dev bash -lc "source /opt/ros/jazzy/setup.bash && source ~/ws_moveit2/install/setup.bash && ros2 action send_goal /hcr_arm_controller/follow_joint_trajectory control_msgs/action/FollowJointTrajectory '{trajectory: {joint_names: [joint_1,joint_2,joint_3,joint_4,joint_5,joint_6], points: [{positions: [1.745329,0,1.570796,0,1.570796,0], time_from_start: {sec: 5, nanosec: 0}}]}}'"
```

```bash
# ⑤ P1 → P2  (base +10° 더, wrist3 +20°, 10초)
docker exec moveit2_dev bash -lc "source /opt/ros/jazzy/setup.bash && source ~/ws_moveit2/install/setup.bash && ros2 action send_goal /hcr_arm_controller/follow_joint_trajectory control_msgs/action/FollowJointTrajectory '{trajectory: {joint_names: [joint_1,joint_2,joint_3,joint_4,joint_5,joint_6], points: [{positions: [1.919862,0,1.570796,0,1.570796,0.349066], time_from_start: {sec: 10, nanosec: 0}}]}}'"
```

```bash
# ⑥ P2 → 홈  (10초)
docker exec moveit2_dev bash -lc "source /opt/ros/jazzy/setup.bash && source ~/ws_moveit2/install/setup.bash && ros2 action send_goal /hcr_arm_controller/follow_joint_trajectory control_msgs/action/FollowJointTrajectory '{trajectory: {joint_names: [joint_1,joint_2,joint_3,joint_4,joint_5,joint_6], points: [{positions: [1.570796,0,1.570796,0,1.570796,0], time_from_start: {sec: 10, nanosec: 0}}]}}'"
```

**속도는 `time_from_start` 가 정한다.** 위는 약 **2°/s** — 검C2 창의 1.25°/s 보다 조금 빠르다.
플러그인 재발행 주기가 **ack 왕복 + 137ms ≈ 200ms** 라 이 속도면 한 스텝이 0.4° 다(중간결과물 §5). 느리게 보려면 초를 늘린다.

### ⑦ 서보 OFF — 끝나면 반드시

```bash
docker exec moveit2_dev bash -lc "cd ~/ws_moveit2 && python3 src/drivers/hcr_comm/tools/mqtt_cmd.py servo off"
```

### ⑧ 스택 내리기

```bash

```

## 3. 아무 때나 쓰는 것

**자세 확인** — 읽기 전용, 로봇이 안 움직인다. 도착 판정은 이걸로 한다(§4 함정 ④)

```bash
docker exec moveit2_dev bash -lc "cd ~/ws_moveit2 && python3 src/drivers/hcr_comm/tools/mqtt_cmd.py pos"
```

**축온 감시견** — 임계 도달 시 스스로 `servo off` 를 쏜다. 동작 **직전에** 별 창으로 띄운다

```bash
docker exec -it moveit2_dev bash -lc "cd ~/ws_moveit2 && python3 src/drivers/hcr_comm/measurements/260812_T15검증/verify/c1_tempwatch.py 192.168.0.20 300 58 /tmp/manual_temp.jsonl"
```

**컨테이너 안에서 대화형으로 작업할 때** — 이때는 `.bashrc` 가 ROS 를 물어주므로 `source` 가 필요 없다

```bash
cd ~/WorkSpace_260814/Nyang_Nyang_Atlier/src/moveit2 && ./run_container.sh shell
```

## 4. 정지 사다리 — 위에서부터

| 순위 | 수단 | 거동 |
|---|---|---|
| 1 | **물리 e-stop** | 유일하게 확실한 수단. PC 명령은 데드맨을 안 거친다 |
| 2 | `docker exec moveit2_dev pkill -INT -f "ros2 launch"` | `on_deactivate` 가 `move/stop` 발행 + 발행을 **영구 잠금** |
| 3 | `… mqtt_cmd.py servo off` | 컨트롤러가 `150026 …_BUT_SERVO_OFF` 로 명령을 거부한다 (실기측 2차 방어선, 검C1 실증) |

⚠️ **`mqtt_cmd.py movestop` 단독은 소용이 적다** — JTC 가 200ms 마다 새 목표를 계속 밀어넣어 곧 재개된다.

## 5. 함정 (전부 실측)

**① `bash -lc` 는 ROS 환경을 안 물고 온다** (2026-08-15 03pc)
`docker exec moveit2_dev bash -lc "ros2 …"` → `bash: line 1: ros2: command not found`.
`.bashrc` 는 대화형 셸에서만 읽히기 때문이다. 위 명령들이 전부 `source /opt/ros/jazzy/setup.bash && source ~/ws_moveit2/install/setup.bash`
를 명시적으로 달고 있는 이유다. 대화형 `docker exec -it moveit2_dev bash` 는 그냥 된다 — **두 형태를 섞으면 되던 게 안 된다.**

**② 여러 줄을 통째로 붙여넣으면 깨진다**
블록 첫 줄이 `docker exec -it … bash` 면 새 셸이 열리고 **뒤따르는 줄들이 그 새 셸의 입력으로 빨려 들어간다.**
그래서 이 문서의 명령은 전부 **한 줄로 완결**되고 셸을 바꾸지 않는다. 함수 정의(`GO() { … }`)도 쓰지 않는다 —
정의는 그 셸에서만 살아서 창을 새로 열 때마다 다시 붙여넣어야 한다.

**③ `c1_tempwatch.py` 는 90초에 끊겼었다 — 2026-08-15 수정됨**
CONNECT 가 keepalive **60초**를 선언하는데 루프가 `recv` 만 해서 브로커가 1.5×60 = **90초**에 끊었다.
600초 창을 걸었다가 **89.15초**에 죽은 것이 발견 계기다(표본 870건 · 임계 위반 **0건** · 최고 **47°C**).
종전 창은 20~22초라 닿은 적이 없었다. 지금은 30초마다 PINGREQ 를 보낸다.
⚠️ 정상 종료 메시지 `✅ 창 종료 — **임계 미도달**` 은 *"임계에 안 닿았다"* 는 뜻이다 — 트립으로 오독하기 쉽다.

**④ `error_code: 0`(SUCCESSFUL)을 도착 판정으로 쓰면 안 된다**
JTC `constraints` 가 미설정이라(중간결과물 §3-D 발견 ④) 추종에 실패해도 성공이 나온다. 판정은 `mqtt_cmd.py pos` 로 한다.

**⑤ 기동 순간 `move/joint/here` 2건이 자동으로 나간다**
`allow_motion=true` 로 활성화하면 궤적을 안 줘도 발행된다(중간결과물 §3-D 발견 ⑦). 그래서 **①(launch) 먼저 → ③(서보 ON) 나중**이다.
서보가 꺼져 있으면 컨트롤러가 거부하므로 로봇은 안 움직인다.

**⑥ 종료할 때 `move_group` 이 exit −11(Segfault)로 죽는다 — 정상이다**
`MoveItCpp` 소멸자 문제로 검B·검C1 두 창 모두 그랬다. 종료 시점이라 무해하다.
다만 **고아 프로세스가 남을 수 있다** — 실제로 `robot_state_publisher`·`static_transform_publisher` 가 남은 사례가 있다.
재기동 전에 확인한다:
```bash
docker exec moveit2_dev ps -ef | grep -E "move_group|ros2_control_node|robot_state_pub|static_transform|rviz2" | grep -v grep
```

**⑦ 서보를 켠 채 오래 두지 마라**
2026-08-05 에 **58~61°C** 에서 6축 드라이브가 0.8초 만에 전부 트립했고 컨트롤러 재부팅으로만 복구됐다
(`hcr_comm/README.md` §8 함정 3). 감시견의 58°C 즉시중단이 그 선이다.
